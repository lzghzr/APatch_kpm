# NoMount

## 模块作用

为 Android 提供基于内核虚拟文件系统（VFS）的文件无挂载注入方案。

常规模块（如 Magisk、KernelSU 或普通 APatch 模块）向系统添加或替换文件时，通常依赖 OverlayFS 或挂载绑定（mount）。这种方式会在系统的挂载列表中留下明显的挂载点痕迹，容易被特定的安全检测识别，或受到只读分区的挂载限制。

NoMount 在内核层直接接管虚拟 inode 与目录项（dentry）查找逻辑，将模块中的系统应用、替换文件或新目录与系统原生目录无缝合并。**整个过程无需任何 mount 或 overlay 挂载，底层系统分区完全保持原样，不产生挂载点痕迹**，在兼顾防检测特性的同时，让系统与各类应用正常读取模块提供的文件。

## 选哪个文件

发布件包含内核模块与用户态配套工具，**两者必须成组使用**：

- `NoMount.kpm`：普通版（动态版），**绝大多数用户选择此文件**。开机加载时由模块自动通过 BTF 或内核特征推导适配设备。
- `NoMount_baselines.kpm`：静态基线件，属于模板文件。需要根据具体机型的内核镜像分析并替换参数后才能使用，直接安装不会生效。
- `NoMount-kpm.zip`：**用户态配套模块（必须安装）**。提供规则管理服务、与内核驱动通信的控制脚本以及 WebUI 图形管理界面。

> 注意：NoMount 必须由内核模块（KPM）和配套模块（ZIP）配合运行，只安装其中一个将无法正常工作。

## 安装

1. 打开 APatch 管理器，进入「内核模块」页面。
2. 先「加载」测试，不报错不死机，再选择「安装」（推荐方式），选取下载好的 `NoMount.kpm` 文件。
3. 安装完成后重启手机，在 APatch 中确认 NoMount 显示为已安装（注：当前最新 11282 版 APatch 并未实装安装成功回显，只显示已安装，哪怕失败了也是已安装，并不能判断是否生效）。
4. 打开模块管理器（APatch / KernelSU / Magisk），在普通模块页面刷入配套的 `NoMount-kpm.zip`。
5. 再次重启手机，即完成全部安装。

## 使用

1. 重启完成后，打开 NoMount 的 WebUI 界面（可通过桌面快捷方式或模块管理器的 WebUI 入口打开）。
2. 在 WebUI 中可以直观查看模块的内核加载状态、当前生效的规则以及注入的文件列表。
3. 支持常规模块中系统应用（APK）与各类系统文件的无感注入，支持按需配置规则、排除特定 UID、跳过不需要加载的模块等。
4. 系统分区全程保持原始只读状态，无需建立 overlayfs 挂载点，各类应用与系统组件均可正常访问注入内容。

## 更新与停用

- **更新模块**：
  - 由于内核驱动与用户态管理工具之间的通信协议有严格的版本对应要求（如 v22），**更新时必须同时成组更新 KPM 和配套的 `NoMount-kpm.zip`**，并重启手机。单独更新其中一方可能因协议版本不匹配而导致规则无法下发。
- **停用或卸载**：
  1. **切勿在系统运行中直接卸载正在工作的内核模块**，否则可能导致系统崩溃或死机。
  2. **停用**：在模块管理器中关闭配套的 `NoMount-kpm.zip` 模块，然后重启手机。
  3. **卸载**：
     - 先在模块管理器中卸载 `NoMount-kpm.zip`；
     - 然后在 APatch 的内核模块页面删除已安装的 `NoMount.kpm`；
     - 最后重启手机。

## 兼容性

- **设备架构**：适用于 Android ARM64（64 位）设备。
- **内核范围**：支持 Linux 内核 4.4 ～ 6.12。
- **机型差异**：各机型厂商定制内核的结构体布局各异，通用动态版开机时会自动检测适配。若因特殊布局识别失败导致模块无法加载，可提取目标机型的 boot.img 制作专属的静态基线件。
