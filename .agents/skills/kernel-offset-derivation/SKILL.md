# 跨版本内核结构体偏移获取

目标：为实际目标内核取得有证据、可核对的结构体偏移，优先复用提取逻辑。早期厂商内核碎片化严重，不保证一个脚本覆盖所有镜像；无法共用时逐镜像现场分析。不能用 `LINUX_VERSION_CODE` 之类的版本判断代替布局证据；实际函数 ABI 无法共用时可按已确认的 ABI 区分基准。

## 决策顺序

先确认用户选择的移植方式。静态模块从目标 img 离线取得固定偏移，填写配置表或替换独立二进制数据段，不引入模块加载时的动态推导。按 ABI 预编译及二进制替换见 [kpm-static-binary-port](../kpm-static-binary-port/SKILL.md)。以下运行时推导用于需要同一产物自行适配多个未知布局的场景。

1. **头文件优先**：拿得到目标内核的 vmlinux.h（BTF dump），且该结构体布局在所有目标版本一致 → 直接 `offsetof()`，编译期固定，零运行时成本。
2. **布局不一致 → 运行时推导**：同一结构体跨版本存在字段增删/移位/位宽变化/kabi 填充（如 `android_kabi_reserve`），头文件给不出一套通用偏移 → 模块加载时从内核自身推导。
3. 推导失败 → 功能降级（安全默认值或跳过该功能）。**不要猜一个偏移硬上**，错偏移轻则数据错乱重则内核崩溃。

旧内核缺少预期函数时，检查功能是否内联、改名或依赖不同内存模型。涉及 Binder 数据读取时阅读 [旧 Binder 数据读取经验](references/legacy-binder-data.md)。来源说明和经验优先用中文记录，保留目标范围与验证边界。

## kallsyms

- 符号来源：内嵌 kallsyms 表自解析（`kallsyms_addresses/offsets`、`names`、`token_table`、`markers`、`num_syms`），或 `/proc/kallsyms`（仅 kptr_restrict=0 时有真实地址）。
- 解析要点：压缩符号名的 token 解码；relocatable 内核地址 = `kallsyms_relative_base + 偏移`；4.x 与 5.x+ 的表项结构有差异，按内容自适应。
- 自提取实现放独立模块，与离线 harness 共用同一套解析逻辑。

## 函数锚点选择（核心）

选一个跨版本都存在、机器码中"依次访问目标结构体全部关键字段"的函数作锚点：

- 优先控制路径函数，不选热路径小函数——后者常被内联进调用者，符号可能不在 kallsyms；
- 函数体内对目标结构体每个待求字段都有一次明确的读或写，且顺序跨版本稳定；
- 有多个候选时全部提取、交叉验证，结果不一致取多数或直接报错，不静默取其一；
- 优先选同时读写"锚点前已知字段"的函数，用已知偏移差校验提取结果。

## 可复用的提取逻辑

对锚函数反汇编，用指令模式与寄存器数据流恢复布局，优先按内容特征自适应。动态模块可使用轻量 AArch64 解码器，离线分析可使用反汇编工具。编译器或厂商差异使算法失效时，检查目标的实际控制流、内联和跳板，再选择其它锚点或手工分析，不按版本号补默认偏移：

- 基址寄存器访存偏移按出现顺序收集 → 候选偏移序列；
- 立即数常量（枚举值、数组长度、mask）作"标记物"锁定字段：某偏移的写入值等于已知枚举 → 该偏移即对应字段；
- 守卫簇：函数开头的连续读-比较 sanity check（读多个相邻字段判断指针有效性）勾勒结构体前部布局；
- 数组内容匹配：已知字符串、已知函数指针表的内容直接定位；
- 跳板解析：CFI/BTI/长跳转 veneer 必须跟随跳转继续解码，否则模式匹配断链；
- 数组元素**步长** = 相邻元素同一字段的偏移差（如 ops[] 的 doit），不要用本地结构体 sizeof；GKI 内核 `android_kabi` 填充会撑大步长，统一算法对"字段间整段零填充"要天然免疫——用相对间隔表达布局，而非绝对值。

## 离线验证平台（harness）

- 用户入口是 img，先解包/解压得到 Image，再取得 kallsyms；裸内核回归语料只是可复用的中间输入。
- 仅运行用户选定的语料范围。动态推导的离线实现应保持与模块算法一致；静态移植则核对本次配置表的完整字段及各自依据，不要求加入模块运行时推导。
- 有参考值的目标要求逐项匹配；相邻版本的输出只能帮助发现异常，不能充当目标偏移的证明。
- 工具失败按未覆盖记录，允许现场分析后补充目标证据。解析器失败不能直接等同于内核没有 kallsyms；符号地址、重定位及后缀的处理见 [静态移植现场适配](../kpm-static-binary-port/SKILL.md#碎片化旧内核的现场适配)。
- 动态模块可打印运行时推导值，与离线结果逐项核对；不一致时查清原因再启用功能。

## 常见坑

- 4.x `/proc/kallsyms` 在 kptr_restrict=1 下地址全为 0，不能当符号表用；
- 重打包/裁剪的内核 Image 段间可能插零填充，解析按字段相对位置而非绝对文件偏移；
- 模块加载器给的静态内存不保证按声明对齐，传给内核使用的缓冲区用内核堆分配（`__kmalloc` 等）；
- CFI 内核禁止把模块函数指针交给内核间接调用，回调只能复用内核已有函数或改走其它通道；
- 头文件里注释掉字段时保持原顺序占位（空行+注释），否则 offsetof 全错。
