# KP 对象关系与行为探测

当已知原生对象、能取得语义明确的接口结果，或需要等真实事件才能确认布局时使用。先复用目标支持的访问器和已确认 SDK 字段，再按 [主技能](../SKILL.md) 的 BTF／有界推导顺序选择方法。以下从仓库 KernelPatch 子模块 `b51197aaba8f2272dd8a3e30c85698a29aa928c9` 提炼；来源实现与本项目采用的接受条件分别说明。

## 已知对象关系锚定

取得对象 A 和 B 的真实地址，先从目标源码或原生接口确认“哪个字段在当前阶段应指向 B”，再在 A 的已确认可读范围内寻找候选。对象符号、原生访问器返回值、已知栈基址和页表地址都可提供锚点，比只判断“像内核指针”更有区分力。

KP 的具体用法：

| 关系 | 实现中的作用 |
| --- | --- |
| `init_task` → `init_cred` | 搜集凭据字段候选；两个成员可指向同一对象，指针相等本身不能区分 `cred` 与 `real_cred` |
| `init_task` 副本 → `init_mm` | 定位 `active_mm` 候选；其依据是该初始化阶段的对象关系 |
| `init_task` → 由 SP 确认的栈基址 | 定位任务的 stack 字段候选 |
| `init_mm` → 已知页表物理地址对应的镜像虚拟地址 | 定位 pgd 字段候选，先转换到相同地址域再比较 |

出处：[task／cred 关系](https://github.com/bmax121/KernelPatch/blob/b51197aaba8f2272dd8a3e30c85698a29aa928c9/kernel/patch/ksyms/task_cred.c#L394-L466)、[stack／pgd 关系](https://github.com/bmax121/KernelPatch/blob/b51197aaba8f2272dd8a3e30c85698a29aa928c9/kernel/patch/ksyms/task_cred.c#L616-L650)。

采用时核对：

- **对象与时间**：确认 A/B 的来源、原生锁／引用及关系成立的阶段。启动时初值不是运行期不变量；访问器若已能完成业务所需读取，优先使用它，不额外扫描字段。
- **地址域**：区分镜像文件偏移、链接地址、运行时 VA、线性映射 VA 与 PA；KASLR、标签及地址转换按目标契约处理。两个 VA 不同也可能映射同一物理页，不能未经转换就否定关系。
- **边界与宽度**：检查候选整个字段都在已确认范围内，按实际宽度和对齐读取，字符串比较同样有界。KP 的 `*_MAX_SIZE` 是该探测的窗口上限，不是目标结构体尺寸；nofault 读成功也不建立对象边界。
- **候选消歧**：收集范围内的候选并按预期角色核对，不取第一个或最后一个相等地址。字段可能共享同一目标、对象可能含多个同值整数；需要原生读取结果或另一语义锚点区分，证据不足就失败。

## 原生接口前后差分

KP 的 `resolve_cred_offset()` 对凭据副本调用 `cap_capset()`，为 effective／inheritable／permitted 设置不同值，再对照原始与修改后内容定位各字段；UID/GID 等路径还结合原生查询结果识别用途。[来源](https://github.com/bmax121/KernelPatch/blob/b51197aaba8f2272dd8a3e30c85698a29aa928c9/kernel/patch/ksyms/task_cred.c#L179-L377)

可借鉴的是“已知输入操作 → 可区分的输出变化 → 原生接口确认语义”，而不是随机写值后看是否崩溃：

- 在有授权的隔离验证环境，或原生 API 支持创建／销毁的专用对象上，比较基线、受控操作和结果。选择可区分各字段的输入，结合接口契约排除计数、padding、缓存及其他副作用。
- API 若可能替换对象或改变持有关系，重新取得有效对象及读取范围，不继续使用旧指针。副本分配容量不证明从原生对象复制同样长度合法；浅拷贝也不取得其中锁、引用和子对象的所有权。
- KP 会记录已识别字段，避免后续把同一位置重复分配给另一字段。复用该思路时按完整字段宽度记录占用范围；只有布局契约明确互斥的字段才要求不重叠，union／位域的合法共享另行核对。

该 KP 路径依赖 `override_current()`，部分探测还会临时改写 `init_task`。普通 KPM 加载时不具备同一前提；不能通过切换 current、改写全局凭据、试写未知成员或临时改页表来完成加载时偏移探测。主动实验保留在明确授权、能隔离副作用且可恢复的验证环境中。

## 在语义成立的事件上观测

KP 并非所有字段都在一次初始化中完成。`resolve_pt_regs()` 注册 execve／execveat 观测，在首次相关调用中用当前三个参数、`orig_x0`、syscall 编号和 x8 的一致关系，从栈顶附近定位寄存器帧。[来源](https://github.com/bmax121/KernelPatch/blob/b51197aaba8f2272dd8a3e30c85698a29aa928c9/kernel/patch/ksyms/execv.c#L25-L78)

借鉴方式是把观测放在已知对象和真实参数同时有效的上下文，用多项关联条件消歧，而不是在任意时刻扩大扫描。核对 wrapper／compat ABI、每次读取边界及匹配的确是本次调用；参数恰好为零或重复时，不能靠相等次数确认帧。

模块原契约允许延后确认时，区分等待、已确认与失败，只开放不依赖缺失布局的路径。观测未发生不等于字段不存在；成功注册 hook 也不等于布局已确认。要求 init 即可用的必要字段仍按原契约失败退出。确认、失败或卸载时按各自生命周期撤销观测，禁止迟到回调重新启用已退出的功能。

## 用硬件配置约束布局候选

KP 从 `TCR_EL1.T1SZ/TG1` 获取内核地址空间宽度和页粒度，并由 `TTBR1_EL1` 取得页表基址；这类参数由运行配置取得，不按内核版本或 Android 大版本猜测。[来源](https://github.com/bmax121/KernelPatch/blob/b51197aaba8f2272dd8a3e30c85698a29aa928c9/kernel/base/start.c#L682-L704)

涉及页表、地址转换或栈几何时，先复用有效且可访问的 KP 配置，确需自行读取时核对目标架构定义及当前翻译区间。不能把内核 TTBR1 配置直接当作用户 TTBR0 配置，也不能把页大小与线程栈大小混为一谈；保留编码和未支持扩展失败，不套用旧掩码继续解释。

[KP 的栈识别](https://github.com/bmax121/KernelPatch/blob/b51197aaba8f2272dd8a3e30c85698a29aa928c9/kernel/patch/ksyms/task_cred.c#L469-L579)还组合 SP、`init_thread_union` 和 `STACK_END_MAGIC` 等证据。可借鉴有限候选与独立基址约束；只有某个候选“包含当前 SP”不证明它就是完整栈尺寸。标记缺失或候选仍有歧义时保留未知，不把历史默认值或按版本选择的尺寸带入模块。

## 逐字段核对 KP 就绪状态

沿调用链核对“谁产生、何时产生、谁消费”：KP 启动钩子中执行 `resolve_struct()`，而 pt_regs 的事件观测在后续另行注册。导出的 task／cred／mm 表有许多成员初值为 `-1`；表已导出、解析入口返回 0，不保证每个成员都已赋值。[初始化顺序](https://github.com/bmax121/KernelPatch/blob/b51197aaba8f2272dd8a3e30c85698a29aa928c9/kernel/patch/patch.c#L69-L109)

KPM 复用前检查运行端导出与实际表 ABI、所需成员的有效哨兵和当前阶段。偏移 0 是否有效按字段契约判断。访问器也要读实现：例如 [`_task_pt_reg()`](https://github.com/bmax121/KernelPatch/blob/b51197aaba8f2272dd8a3e30c85698a29aa928c9/kernel/patch/common/utils.c#L126-L150) 在 `pt_regs_offset` 未取得时会转入按版本选择的尺寸；调用成功不自动成为有证据的动态推导。已有功能按原契约维护，新能力不把这种回退当作布局证明。
