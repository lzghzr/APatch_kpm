## 详细测试记录与现场事实

### 趟 ①：4.19 动态版（缺口验证）

1. **引导与初始化日志**：
   ```text
   [    2.840861] [+] KP D loading module: 
   [    2.840864] [+] KP D     name: NoMount
   [    2.840868] [+] KP D     version: 2.1.1-20261014
   [    2.840872] [+] KP D     license: GPL v2
   [    2.840877] [+] KP D     author: maxsteeel, Codex
   [    2.840881] [+] KP D     description: NoMount: read-only file and directory views, resident until reboot
   [    2.840927] [+] KP I alloc module size: 18169
   [    2.908962] NoMount: layout: file objects=32/32 mapping=240
   [    2.908977] NoMount: layout: inode sb=40 ino=64 size=80 nlink=72/72
   [    2.908983] NoMount: layout: dentry ops=96
   [    2.932870] NoMount: initialization failed: -61
   [    2.932877] [+] KP I load_module_ex: [NoMount] failed with [(null)] error: -61, try exit ...
   [    2.932898] KP load kpm: NoMount, event: pre-kernel-init, rc: -61
   ```
2. **分析与事实判定**：
   - 动态版在 4.19 上成功完成了基础 VFS 布局推导（`file`/`inode`/`dentry` 偏移）；
   - 在进入 `nm_prepare_control_engine()` -> `calculate_btf_control_layout()` 时，函数强制要求通过 BTF 解析 `mutex`、`key_type` 与 `key_preparsed_payload`；
   - 因 4.19 无 BTF，`nm_get_btf` 返回 `-ENODATA`（`-61`），且 control layout 没有非 BTF 降级路径，模块遵循安全原则 **Fail-closed** 主动退出；
   - KP 捕获 `-61` 错误后安全卸载，内核与系统单调启动至 `sys.boot_completed=1`，未发生死锁、Panic 或崩溃。

## 结论与建议（致维护者）

1. **发布结论**：
   - **4.19 静态版** 与 **4.4 静态版** 在各自目标真机上全功能验证通过，版本号、CLI、驱动通信及用户主路径 20/20 判据全部 PASS；
   - 配套 ZIP `NoMount-kpm_2.1.1-20261014.zip` 在两台设备上均能正确安装、识别驱动 `2.1.1-20261014` 并部署用户态工具。
2. **关于动态版在旧内核上的事实依据**：
   - **Linux 4.19**：动态推导在无 BTF 时无法解析 control layout，安全 fail-closed 退出（`rc: -61`）；
   - **Linux 4.4（旧版 KP）**：缺少新版 KP 导出符号 `kallsyms_lookup_name_by_suffix`，KP 安全拒绝加载（`rc: -2`）；
   - **技术建议**：动态版本在无 BTF / 旧 KP 环境下均能安全退出且不致死机，但无法提供服务；建议维护者与用户确认，在 README 中明确**旧内核（如 4.4 / 4.19 等无 BTF 目标）请使用预置偏移的静态基准版（`_baselines.kpm`）**。
