# HMA Guard 实现笔记

这次实现的经验可以归结为三件事：先取得完整可信的策略，再保留原生语义，最后减少查询路径中的额外工作。以下来自 ARM64 Android 6.12.69 目标，其他目标的布局、函数签名与调用入口须重新核对。

## 分开应用列表、UID 枚举和 SELinux 查询

应用列表继续由 HMA-OSS 处理。内核侧 UID 防护只处理启用 seccomp 的 App 对其他 App UID 发起的用户范围请求；系统 UID、自身 UID、PID 与进程组查询保留原生行为。

SELinux 的查询和执法也要分开：查询返回合法 context，不等于允许进程切换到它。真实权限检查、SID 登记与进程转换应由原生 SELinux 完成。

## 策略必须可信，也必须完整

原厂预编译策略不一定是本次启动实际使用的策略。Android init 可能因输入校验不匹配，改为从多个分区的 CIL 现场编译；旧策略即使能解析，也可能缺少当前固件的合法类型。

能提前入驻时，可在 init 首次加载的输入有效期内重建独立 `policydb/sidtab`，待原生 commit 成功后发布。prepare 成功不等于提交成功；失败或 cancel 要释放候选，不能借用已经失效的输入指针。首次输入还须早于框架注入，来自可信固件。

只能晚加载时，按 init 的实际分支准备同固件的完整外部策略。mapping、compat、genfs 输入和编译参数分别核对；内核 `policyvers` 是支持上限，不是必然的输出格式。不要把 `su` 或整段策略中的 `ksu` 子串当作污染判据，合法策略也可能包含它们。

## 跨策略按语义同步

clean 与 live 中相同的数值类型编号不保证代表同一类型。跨策略同步使用 context 文本语义，不能直接复用类型编号。

长文本中的重复 MLS 类别可能表示同一 context。先经 clean 解析，再序列化为规范文本供 live 登记，可减少第二遍解析的冗余工作；context 应答还可以复用该缓冲。优化须保留原有权限检查、错误处理与 SID 登记语义。

## attr 转换优先交回原生路径

本例只对有限类型做有界分类，其余请求原样交给原生 `selinux_setprocattr`，不模拟完整的进程上下文转换。

LSM 分发表入口可以减少函数正文重定位引入的变量，但不能只凭结构体名字选择槽位。要核对实际调用者、BTF 布局、函数原型、KCFI/BTI、写入原子性与页面权限；所有可失败初始化完成后再发布回调。

## 就绪状态与资源生命周期分别处理

模块初始化成功、影子状态页存在、策略副本就绪是三个状态。副本不可用时应明确报告能力范围，不能静默当成完整查询视图。

状态页在 open 时绑定 FD；跨 UID 传递、继承 FD、既有 mmap 与控制开关都要遵守这个生命周期。已发布的页和回调在所有引用退出前不能释放。本例保留资源至重启，不支持热卸载。

## 差分计时先定位额外工作

- 总开销不等于差分开销：A、B 同时变快，A−B 未必改变。
- 宿主微基准不能直接换算成目标机收益；计时阶段应关闭插桩和日志。
- 以成对差值统计，不能用两个独立中位数相减代替 paired 中位数。512 个差值的下中位为正，至少需要 257 对为正。
- 关闭业务开关不等于未加载：hook、已有 FD 与 mmap 可能仍在。
- 同一次开机的重复批次不是独立开机样本。没有内部读数时，不把“某个缓存变热”当作已证实原因。

先确认合法 App 启动、查询语义和设备存活，再比较性能。单次检测结果不能代替跨开机对照，也不能承诺差分归零。
