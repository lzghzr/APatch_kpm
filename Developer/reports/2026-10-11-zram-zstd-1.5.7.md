# zram_zstd 1.5.7 试升级

Developer；2026-10-11。模块源码已升级为 0.3.0，ZSTD 子模块固定到官方 `v1.5.7-kernel` 的 `5d9fb4785030731a155a8abe159e10965d824e4b`。本轮结论来自实现方自检（构建 + 离线语料 + 代码走查），不是独立审计，也不是实机结论。

[完整自检数据](data/2026-10-11-zram-zstd-1.5.7.json) 记录四份普通产物的完整 commit、instance_id、SHA-256、工作树指纹、派生兼容产物、三份镜像身份和测量原始值。统一构建以 `d697f92382bbdf7e150078acd6d19da206bedf27` 为基线，明确标记 `source_dirty=true`、`kind=exploration`；基线提交不能单独复现升级后的工作树，正式交接还需冻结全部输入后重新构建。

## 实现

- 使用上游 freestanding 生成器及官方 kernel `mem.h`／`zstd_deps.h`，提交、95 项输入文件及生成选项由 `SOURCES.json` 核对。生成源码与其清单只写入新的输出目录，子模块工作树保持干净。
- xxHash 从同一子模块按原字节保留；构建启用静态状态声明并禁用库内动态分配。官方内核生成器默认面向内核 xxHash 导出，因此本模块在生成后复制原文件，以保持完整自带实现。
- 改用 `ZSTD_estimateCCtxSize(3)`／`ZSTD_estimateDCtxSize()` 与 `ZSTD_initStaticCCtx()`／`ZSTD_initStaticDCtx()`。估算错误在分配前返回；transform 创建时分配、退出时释放，单次编解码保持级别 3，热路径使用已有工作区。
- 原生算法检测、注册布局、BTF／短函数分层、`post-kernel-init`、常驻生命周期和控制接口保持原契约。README 区分新版宿主自检与旧版实机证据。
- 当前版本的三个登记字段经用户授权更新到 0.3.0；历史构建、审计、测试和问题结论保持原记录。配套补丁保存在 [version.patch](../proposals/2026-10-11-zram-zstd-1.5.7/version.patch)。

- 4.4.192、`kernel_mi8-4.9`、`kernel_mi9-4.14` 均通过现有 ASan／UBSan 宿主自检。每份包含实际入口推导、BTF 缺失回退及有效 BTF 错误传播、64／128 名字布局、短锚点负例、256 页编解码与独立 libzstd 双向互解、ctl0 边界、分配失败和重复清理。

- 四份普通 KPM 的隔离构建与实际统一构建结果逐字节相同。四份普通件加原名函数指针夹具通过兼容自检，覆盖直接调用、既有指针导入、精确元信息修改、静态 JSON、回执范围及输出保护。普通／debug 两份 Python 兼容转换样本已生成；正式 legacy 实例仍须在冻结受控配方中捕获转换命令。

## 成本与收益

比较同一 4.4 镜像前 256 个 4096 字节页面；宿主编译使用相同 `-O2 -fno-strict-aliasing`，每版三次测量。使用实际移植 codec，压缩级别均为 3。原始数据和 [测量源码](data/2026-10-11-zram-zstd-benchmark.c) 已保存。

| 项目 | 1.3.1 | 1.5.7 |
| --- | ---: | ---: |
| 压缩工作区／transform | 1,289,144 字节 | 1,303,568 字节 |
| 解压工作区／transform | 155,984 字节 | 95,968 字节 |
| 两工作区合计 | 1,445,128 字节 | 1,399,536 字节 |
| 1 MiB 样本压缩后 | 670,445 字节 | 651,280 字节 |
| 普通动态 KPM | 230,872 字节 | 508,040 字节 |
| 宿主压缩吞吐中位数 | 161.043 MiB/s | 284.137 MiB/s |
| 宿主解压吞吐中位数 | 435.346 MiB/s | 720.781 MiB/s |

该样本压缩体积减少约 2.9%，每 transform 工作区合计减少约 44.5 KiB；KPM 约为原来的 2.2 倍。吞吐样本有波动，仅支持继续试升级，不能代表 Android zram 的实际收益。

## 决策（Decision）

**保留（Retain）**

## 方案挑战

### 有效性

上游 API 明确单次编解码静态工作区契约，当前对齐、估算大小、无字典调用和分配时机与之相符；三份既有目标及独立互解通过。反例检查发现的 xxHash 静态状态声明与宏重定义问题已在试验中修正，最终构建再次通过。

### 简洁性

复用固定子模块中的生成器与内核依赖适配，仅增加所需兼容头和静态 API 接入。保留 1.3.1 能维持原行为，但不能满足本次升级目标；自带 xxHash 避免引入新的目标内核符号契约。

### 后果

算法和工作区实现变化需要重新独立审计及真机测试，旧版结论继续绑定旧字节。主要可见成本是 KPM 体积增大；宿主压缩和工作区结果支持保留试升级，实机并发、注册、内存回收与换页压力仍待验证。

## 修订建议

采用当前 1.5.7 源码作为下一轮冻结输入，保持现有旧内核接入范围；先完成新版独立审计和实机验证，再评估后续内核适配。按 are-you-sure 完成有界只读反例检查，按 no-negative-echo 回读源码、文档及实际回执，按 respect-the-oracle 保留原判据并记录 Developer 自检边界。
