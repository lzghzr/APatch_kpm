## 共用实现中的接口选择

表从 38 字段／76 字节扩为 42 字段／84 字节，原字段顺序不变，增加以下独立接口选择：

| 字段 | B2N 4.4 | 已知 4.19 配置 |
| --- | --- | --- |
| getattr_callback_args | 3：mount/dentry/stat | 4：path/stat/mask/flags |
| getattr_function_args | 2：path/stat | 4：path/stat/mask/flags |
| kstat_inode_first | 1：ino 位于 0，dev 位于 8 | 0：使用 statx 前部布局 |
| name_hash_args | 2：name/length | 3：salt/name/length |

目标 `full_name_hash` 首三条指令使用 x0 字符串、w1 长度；`vfs_getattr_nosec` 从 path/stat 构造 mount/dentry/stat 调用；`generic_fillattr` 对 kstat 的实际写入位置与 inode-first 声明一致。调用通过对应类型的函数指针和回调包装进入共用业务逻辑。4.4 没有 iterate_shared 与 d_init 槽，以 -1 表示已确认不存在；保留原 iterate 和 release 槽。

新增字段初始为未知，未完整确认时拒绝初始化。新增 [4.19 v2 配置](../../nomount/configs/boot_los23.2-v2.json) 显式填写原 4.19 的四项调用值；0.1.0 配置保留，避免改写旧绑定。接口选择不按内核版本号猜值。运行时 BTF 路径独立验证函数签名与 kstat 字段；本轮只完成其编译，没有新增 BTF 正例执行，也没有 4.4 动态加载证明。

## 自检结果与边界

- 四种正式构建通过。SDK 的 READ_ONCE／WRITE_ONCE 重定义产生既有警告，其他警告按 Werror。新增 C/h 格式检查及差异空白检查通过。
- 宿主 ASan／UBSan 契约通过：保留原生成控制 Oracle 的全部 577 个 assert 表达式与顺序，再增加两参数哈希、两参数原生 getattr、三参数 inode／目录回调选择、未知／非法 ABI 拒绝、kstat 写入边界和错误传播用例。23 份已有 test_*.py 逐字节对照原提交保持不变。
- 两份静态件只改变配置表的 84 字节；JSON 与 blob 结果一致，恢复 -1 模板后逐字节等于 base。两份旧 KP 转接只在回执记录范围内变化，目标配置随配套 JSON 保留。
- 4 份候选与 4 份派生件的 ELF、内嵌身份及静态布局核对通过。未定义导入均存在于冻结 SDK 的导出定义中；实际反汇编操作数未发现 FP／SIMD／SVE 或 x18 使用。导入包括 `compat_copy_to_user, cred_offset, kallsyms_lookup_name, kallsyms_lookup_name_by_suffix, kf_memchr, kf_memcmp, kf_memcpy, kf_strcmp, kf_strncmp, printk, sp_el0_is_current, sp_el0_is_thread_info, task_in_thread_info_offset, task_struct_offset, thread_info_in_task, thread_size`；没有裸 memcpy/memset 导入。

这些都是 Developer Tier 3。宿主原生接口与锁是夹具，不能证明真实并发、keyring 权限、RCU、CFI、SELinux 或 PackageManager 行为；4.4 尚无实机结论。新版共用逻辑的 4.19 宿主回归通过，不自动继承 0.1.0 的运行结论。原 test_kpm.py 中 38 字段／76 字节检查属于 0.1.0 的冻结基准，本轮没有改写它或声称它在 0.2.0 直接通过。

### Oracle 输入迁移与开发失败

本轮新增脚本以原提交的来源哈希校验控制 Oracle，替换已变动的真实生产函数，**仅为新增字段显式填写 4.19 夹具输入**并按当前版本宏运行；逐项确认全部原 assert 未变。宿主桥接仍保留原 fixture lookup，ELF section 属性只在宿主生成文件中移除。请 Auditor 独立复核迁移范围与新调用桩。

探索自检曾暴露全零布局返回码回归：加入 ABI 验证后先返回不支持，而原 Oracle 要求 EINVAL。实现改为先验证结构几何，再核对 ABI，恢复真实无效输入语义，原断言保留。另有两次新脚本生成桥接错误及一次宿主 ELF 属性错误，修正范围限新增工具；首次 ARM64 声明复现与宿主标准库类型冲突，改为无 stdio 的目标声明编译。最终有效记录为 contracts-06、layout-reference-03 与 shared-prefix-01。未交接的这些编译／夹具错误按开发记录保留。

## 复核决定（Decision）

**修改（Modify），已落实到冻结候选。**

### 有效性

有界 Developer 挑战指出新 ABI 字段不能默认沿用 4.19：旧配置漏项可能使 4.4 调用参数和属性写入错误。实现改为默认未知、目标显式填写、发布前验证；577 条原断言及新增拒绝用例通过。目标指令和 ARM64 声明分别提供接口与布局依据。

### 简洁性

基线 0.1.0 固定使用四参数 getattr／三参数 hash，无法满足此目标。四项选择彼此独立，共用已有 VFS 实现和 nm_structs.h 前部；静态变换继续使用现有 patch_offsets.py。没有更简单且能保留两种原生契约的已证基线，不增加加载参数。

### 后果

42 字段要求使用配套新布局；原 0.1.0 配置保留并新增 v2 文件。模块继续常驻到重启；错误卸载仍可使原生回调指向已释放代码。现有 RA-002 只覆盖旧版本及目标，维护者需为新候选确认适用范围。4.4 加载与业务安全仍由独立审计和真机事实判断。
