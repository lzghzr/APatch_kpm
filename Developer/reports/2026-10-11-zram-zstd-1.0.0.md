# zram_zstd 1.0.0 算法列表显示与候选交接

源码冻结提交：`c068b23c8be43d3652780ed8f079bfe3b9799203`。用户指定本轮版本为 1.0.0，目标 zram 与 KPM 常驻。四份候选的完整身份见下文和[交接清单](handoffs/2026-10-11-zram-zstd-1.0.0-candidate.json)。本报告属于 Developer 宿主自检（Tier 3），独立审计与真机测试待对应角色完成。

## 行为

算法注册成功后，zram 的 `comp_algorithm` 列表显示未选中的 `zstd-kpm`；已有选中标记和其它算法保留。开机脚本与管理工具继续负责选择算法、初始化容量和交换空间。

`zs_display.c` 先接入 `do_init_module` 的加载完成入口，再检查已有 zram。原生函数成功返回后重查目标；所有安装由原生 `module_mutex` 串行。查到地址还须确认属于核内代码或 LIVE 的 LKM，COMING 不安装。读取的 module state 首字段放在 `zs_structs.h`，由本轮实际目标证据核对；没有增加偏移表字段或运行时指令扫描。

列表 after 回调仅匹配完整 token。写入限于当前 4 KiB 子页剩余空间，保留已有前缀，并计入结尾 NUL；覆盖 `recomp_algorithm` 的页内偏移和 ARM64 4/16/64 KiB 页。错误返回、未终止行、空间不足或已有算法均保持原输出。注册后显示功能失败只降级为直接写入算法名，保留已登记的 Crypto API 回调。

原生加载入口与接口依据：[5.15 module.c](https://raw.githubusercontent.com/torvalds/linux/v5.15/kernel/module.c)、[6.6 main.c](https://raw.githubusercontent.com/torvalds/linux/v6.6/kernel/module/main.c)、[算法列表接口](https://raw.githubusercontent.com/torvalds/linux/v5.15/drivers/block/zram/zcomp.c)。`do_init_module` 声明为 noinline，完成成功初始化及原生锁释放后返回。
