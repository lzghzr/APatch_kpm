# 低版本兼容：只改二进制，不改源码

KPM 的源码与构建只面向**最新 KernelPatch**；对旧内核的兼容以**二进制后处理**实现，作为独立派生件交付。

## 规则

1. **源码与 Makefile 只面向最新 KernelPatch**
   不出现 `-DCONFIG_KPM_LEGACY` 之类分支，不为旧内核改动业务实现，`Makefile` 里不放生成兼容件的目标；
   构建输入集合里也不含 `patch_offsets.py` 等兼容工具。

2. **兼容只在产物上做**
   对已构建的 `.kpm` 做字节级变换（`patch_offsets.py legacy-kp`），产物是**派生件**，不是另一个构建变体。

3. **派生件必须可追溯**
   记录 `base instance_id + source_commit + base 产物 sha256 → 变换（工具路径 + 工具 sha256 + 完整命令）→ 派生件（名称 + sha256 + 大小）`。
   任何设备证据、验收或交付若使用派生字节，必须同时写明 base 实例与派生哈希。

4. **门禁不设兼容要求**
   `kp_compat` 是**可选**自识别字段，省略即视为未声明；`_legacy` 命名后缀可被接受，但不是要求。

5. **变换要独立复核**
   字节级变换直接改变内核里执行的内容；派生物要交付或用于真机结论时，变换工具与契约须经独立复核。

## 归属

派生件的生成归 **Developer**（随候选交接一并提供；缺失时由维护者提醒补齐）；**Tester 只做真机测试**；
维护者负责登记与核对。派生件统一落在 `artifacts/binary-port/<模块>/<派生件 sha256>/<派生件名>`，
目标身份记在元数据与回执里、不进路径。

## 移除条件

目标 KernelPatch 版本修复旧版兼容问题后，本路径即可删除。
