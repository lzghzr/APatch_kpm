## 流程变更（用户 2026-10-14 定，已写入仓库判据）

**真机只测一个变体**：`debug` 相对 `release` 只增加日志/断言详细度 → 真机测试**每个目标只测一个变体（优先 `release`）**，未测变体由验收以审计确认的「变体差异」结论绑定。
判据见 `AGENTS.md`（KPM 偏移模式段）、[`docs/process/tester-handbook.md`](../process/tester-handbook.md) §4.1、[`docs/process/05-maintainer-acceptance.md`](../process/05-maintainer-acceptance.md)。

## 致 Auditor

1. **变体差异（本轮新增，支撑上面的判据）**：对每个目标**独立比对 `release` 与 `debug` 产物**，判定差异是否**仅限于日志、断言与版本/调试字符串**（不涉及业务分支、偏移表、协议、回调集合、调用序列）。
   - 结论为「仅日志/断言」→ Tester 可只测一个变体；
   - 未确认或超出范围 → **fail-closed，两个变体都要测**；
   - 请在报告中逐目标给出该判定，作为验收绑定未测变体的依据。
2. **本轮两处改动**：私有分配优化（0.4.2）与 inode 绑定解耦（0.5.0）的语义与边界；是否引入新的生命周期／引用计数风险。
3. **上游未移植项仍待评估**：规则内联存储、inode 与 rule 解耦、RCU 规则退役、整批 ADD 锁重构、UID Bloom、名称查找热路径优化——是否含**必须随本轮发布的正确性/安全性修复**。
4. **候选与派生件**：独立重编译 12 份候选、独立重跑 36 条目标变换并逐字节比对。
5. 报告按完整 commit + instance_id + 产物 SHA-256 绑定身份。
