# 报告与证据分层存储提案

状态：提案，尚未修改现有门禁契约或迁移归档。角色：维护者。

## 现状

按本轮登记前的 Git 文件树统计，Auditor、Developer、Tester 三个目录合计约 25.6 MiB，metadata 约 9.5 MiB，均为未压缩的当前文件大小。最大单个模块元数据约 4.45 MiB，最大产物审计 JSON 约 2.49 MiB。文本报告本身占比很小，大头是重复的清单、输入列表和逐项产物解析结果。

压平提交会减少提交历史，但保留在最终树中的报告仍会发布。Git 的压缩和差分复用会减少实际传输，目录大小不等于上传量；本次未测 GitHub 端存储或单次推送流量。当前体量值得优化维护成本，不能据此认定已经超过托管限额。

## 建议流程

| 保存位置 | 保存内容 | 原则 |
| --- | --- | --- |
| 代码仓库 | 各角色最终报告、问题与关闭记录、完整身份、覆盖限制、证据清单及引用 | 报告由原角色形成；总结保留失败、未覆盖、风险和结论来源 |
| 独立证据归档 | 完整脱敏报告、逐项数据、构建清单、必要的冻结源码及工具对象 | 内容按哈希定位，只追加；可压缩封包，逐文件校验；公共材料可由用户随发布提供独立附件 |
| 本地受控原始档 | 未脱敏日志、设备现场及原始报告 | 保留原字节及其哈希；与脱敏版本关联，按原有隐私边界保存 |

代码仓库中的每份结论引用：完整 source_commit、instance_id、产物 SHA-256、报告作者/角色、工具身份、关键结果/计数、未覆盖项、证据清单哈希与取回位置。清单至少列出每个文件的相对路径、长度和 SHA-256，并记录封包哈希、脱敏来源与转换关系。更正继续保留历史版本及追加关系。

归档以冻结版本或内容哈希定位，不覆盖同名附件。只要某结论仍用于交付，该结论所依赖的证据及冻结对象就必须可取回；压平后的源码快照不能代替原 source_commit。私有原始材料与公开脱敏包分开，不能将未经全历史卫生检查的 Git 对象包直接公开。

每轮只归档新增证据，已有证据引用原哈希；公共最终报告集中说明本轮有效结论及追溯路径。复核仍按实际影响决定全量或增量范围，保留失败与推翻过的结论，避免每轮把相同大清单重复嵌入多个 JSON。

## 完整性与可核查性

哈希证明取回的字节与登记一致，不能单独证明报告真实或测试确实执行。真实性继续依赖独立角色、绑定的工具与产物、原始观测、可复现步骤及后续签名绑定。分层存储改变保存位置，不改变这些要求。

正式验收仍核对证据内容。新的解析机制应支持本地缓存或取回后的归档，检查清单路径安全、完整性、报告版本前缀、身份匹配和引用完整性；缺包、缺文件、哈希不符或不可复算按原判据失败。日常源码 CI 可只跑与源码相关的检查，不能因此宣称交付证据已验证。

现有门禁要求报告已入库、路径在场，因此不能只删除文件再写一个下载链接。迁移需由维护者调整存储契约，补正反夹具并经独立复核；验收的身份、原文保护、独立关闭和可复算要求不放宽。

## 采用顺序

1. 本轮先完成登记，保持当前证据。后续新轮次让各角色同时产出精简最终报告与完整证据包。
2. 先试运行封包、取回、逐文件验包和原文版本链核验，使用现有证据作等价性对照。
3. 独立复核通过后采用新契约；归档及备份恢复验证完成前保留原件。
4. 已发布历史不为体积优化改写。旧文件仅在归档引用可验证且迁移获授权后处理。

封包附件减少每次源码克隆所携带的数据；若仍存 GitHub，托管数据并未消失。真正减少重复存储依赖引用复用与清单去重。不能仅靠压缩格式或另建仓库保证总存储下降。

GitHub Actions 日志与 artifacts 有保留期，不作为唯一长期证据库。公共脱敏证据可选发布附件，私有原始证据继续由受控存储保管；备份归档与代码仓库 Git 快进同步是不同操作，不混入既有 SMB 同步步骤。

参考：[Git 差分压缩](https://git-scm.com/docs/git-pack-objects)、[GitHub 仓库体积说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)、[Actions artifacts 保留期](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts)。
