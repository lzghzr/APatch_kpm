# 新生成交接数据复用

角色：维护者。报告继续通过 Git 保存完整原件与追加历史。本轮优化新清单的生成表示，不重写已有清单、封存 MANIFEST、角色报告或构建身份。

## 生成与读取

`tools/identity.py` 和 `tools/build_candidate.py` 增加 `--shared-inputs`，与 `--handoff` 一起使用。旧格式仍可生成和导入；新格式为自包含 JSON，不依赖压缩包或外部数据服务。

```bash
python3 tools/build_candidate.py <模块> --toolchain <标签> --target all --handoff <新清单路径> --shared-inputs
python3 tools/identity.py import-manifest <清单路径> --by 维护者
```

`handoff_schema=2` 在同一份清单内只保存一次重复的大块输入：`sources`、`recipe`、`build_transaction`。构建条目以 `{"data_ref":"<SHA-256>"}` 引用顶层 `shared_data` 中的完整值。哈希针对 UTF-8 JSON、字典键排序、紧凑分隔符计算；数组顺序、原始参数字符串与字段类型保持原样。只复用至少 512 字节且重复出现的数据；没有重复块时继续生成旧格式。

读取先校验共享块哈希和引用完整性，再展开成原始结构，之后执行既有 source_commit、instance_id、指纹、事务和产物检查。单实例 MANIFEST 与模块元数据仍使用原格式，原有历史记录完全保留。缺失块、篡改值、未知 schema、伪布尔 schema、额外引用字段或未使用的共享块均拒绝。

门禁将新表示的引用完整性并入既有 `report_integrity`，常规与 strict 均拒绝悬空引用；导入入口完整展开后运行原核验。此机制改变数据表示，不改变候选或交付判据。新格式为显式选项，其他角色独立读取器采用前应自行核验协议，不能把维护者解码输出作为独立审计依据。
