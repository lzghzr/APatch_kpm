## 本轮主张（待独立核实）

1. 新建清零表的**分配容量**与原生表的**复制长度**分离：`original == NULL` 时用自建容量（无 BTF 时 **512 字节**），非 NULL 时仍按精确尺寸分配与复制；
2. 容量只在 **BTF 明确不可用**时启用；有效 BTF 错误继续传播；
3. `key_type_size` 保持未知但**不再阻塞**新 key 对象分配与控制布局校验；
4. 原生 inode/super/dentry 代理的 `memcpy`/`memcmp` 与完整尺寸校验**保持精确取值**，多分配的内存未用于扩大源读取；
5. 512 字节来自已核对 ARM64 声明的保守预算（4.4 inode_operations 28 个函数指针 → 上界 256B；dentry ≤192B；key ≤200B，`lock_class` 按 32B 计入；含字段重排/自然对齐/64 字节表对齐）；
6. **仍缺** `inode_ops_size`、`super_ops_size`、`dentry_ops_size` 三类原表的复制范围，未取得时完整准备仍返回错误。
