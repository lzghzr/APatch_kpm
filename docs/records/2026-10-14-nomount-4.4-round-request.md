# nomount 4.4 适配轮次请求（Developer 实现 + Tester 并行验证）

角色：维护者。依据 `nomount/README.md`「适配顺序」（4.19 → **4.4** → 5.15）与 `nomount/AGENTS.md` 约定；用户已选定 4.4 目标镜像。

## 一、致 Developer：4.4 目标适配

**目标镜像（唯一）**：`kernel_img/B2N-416G_boot.img`（Nokia 7 plus，内核 4.4.192），镜像 SHA-256 `ea919143cb1f057f3d35d726294166d5186f376e9751941b83940e75d48a288c`。
该镜像**无 BTF** → 走**静态**路径：填写目标配置并用静态 baselines 产物；动态版在 4.4 上无 BTF 可用时按模块既有规则失败退出，不得猜偏移。

需要交接：

1. `nomount/configs/<目标>.json`：偏移表 + 镜像/源码/证据绑定（沿用 `boot_los23.2.json` 的 schema 与字段语义）；
2. 从**冻结提交**构建的候选（`python3 tools/build_candidate.py nomount --toolchain <tag> --target "all debug" --handoff`），交接清单写明实例与产物哈希；
3. **目标静态派生件**：`python3 patch_offsets.py patch <在册 baselines 产物> --offsets nomount/configs/<目标>.json --layout <同名 .kpm.json> --output artifacts/binary-port/nomount/<派生 sha256>/<名字>`（落盘位置按仓库统一约定）；
4. **若 4.4 的 KernelPatch 缺 `kallsyms_lookup_name_by_suffix`**：按既有规则在**已构建字节**上做 `patch_offsets.py legacy-kp` 派生件，**不得**在源码/Makefile 里加低版本兼容分支；派生件随交接一并提供；
5. 版本声明由你提出（沿用版本提案模式），维护者同步元数据。

## 二、致 Tester：开机扫包与新应用启动验证（与上面并行）

对象：4.19 目标在册静态派生件 `a3694526cac5c4cef05fd6b5326790101513f42c31094203c648618898ba7dcb`（base 实例 `nomount-0.1.0_baselines+…rde831ef7…#1`），设备 Sony Xperia 1 II / 4.19.325。

要验证（`README.md` 明列的待验证项）：

1. **规则先于系统应用扫描建立**：给出时序证据（规则下发时间戳 / `nm list` 输出 与 开机 `logcat`/`dmesg` 中 PackageManager 扫描阶段的先后）；
2. **PackageManager 完整扫包**：`pm list packages`、`dumpsys package <pkg>` 对**规则新增的系统应用**的可见性（与 root 视角对照）；
3. **新应用启动**：安装一个测试 APK 并启动，确认其资源/APK 可读、能正常起来（记录 `getPackageCodePath()` 路径与读取结果）；
4. **Dexopt 触发扫包**：`cmd package compile -m speed <pkg>` 后重复第 2、3 项；
5. **阴性对照**：同场景下未隐藏应用行为不变，排除 SELinux 误判；
6. 记录 **UID + SELinux 上下文 + 精确命令 + 原始输出**；弱证据只写「未观察到」。

## 约束（两方共同）

禁止卸载与动态重载（`RA-002`）；死机/卡死立即停止并升级；结论只对该机型/内核/场景有效，不得外推。
