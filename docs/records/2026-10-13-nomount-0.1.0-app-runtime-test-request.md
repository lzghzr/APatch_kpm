# 追加测试请求：nomount 0.1.0 应用侧（非 root / UID 隔离）运行时行为

角色：维护者 → Tester（主）；Developer 仅在需要探针 APK 时参与。
依据：Tester 未覆盖清单第一条（带 UID 隔离的非 root 应用访问）；Developer `nomount/AGENTS.md`「PackageManager 的扫描成功不代表应用进程读取成功」。

## 为什么要加

现有 12 项强判据全部是 **root/系统视角**；而 NoMount 的核心承诺是「**应用看不见**」。非 root 应用运行在 `untrusted_app` 域，LSM 检查路径与 root 不同；`mmap` 走 `file_mmap`，与 `read_iter` 是**不同 hook 点**，只测读可能漏。

## 主探针：Termux（现成 App，无需自建 APK）

Termux 的进程以**自身 UID** 运行在 `untrusted_app` 域，可直接在应用侧做精确探测：

1. **记录身份**：`id`、`cat /proc/self/attr/current`（SELinux 上下文）、`getprop ro.build.version.release`；
2. **读**：`cat <被隐藏文件>` → 期望 ENOENT/EACCES，记录 errno 与 stderr 原文；
3. **元数据**：`stat`、`ls -l`、`readlink`（符号链接时）；
4. **目录枚举/合并**：`ls -la <被合并目录>` 逐项记录，并与 **root 视角**同一目录对照；
5. **mmap**：`python3 -c "import mmap,os;p='<路径>';f=os.open(p,os.O_RDONLY);m=mmap.mmap(f,0,prot=mmap.PROT_READ);print(m[:16])"`（Termux 内装 python）；
6. **映射泄漏**：mmap 成功后 `grep <路径> /proc/self/maps`；
7. **阴性对照（必须）**：对同目录**未隐藏**文件重复第 2–6 步，必须全部成功——否则说明是 SELinux 拒绝，而非 NoMount 生效。

## 次探针（UI 层交叉验证）

开源文件管理器（**Fossify File Manager** 或 **Material Files**）以普通应用身份列目录、打开文件，用于确认**用户可见**的目录合并结果。

## 可选（仅当需要 PackageManager 路径覆盖）

需要一个探针 APK：调用 `getPackageCodePath()` / `getPackageResourcePath()` 后 `open`/`mmap`。
本机 Android SDK 只有目录骨架（无 `platforms/android.jar`、无 `build-tools`）→ 若确需，请 **Developer** 提供（源码 + 构建命令 + APK SHA-256 + 安装方式）。

## 判据与记录

- 每条记录：**UID、SELinux 上下文、精确命令、errno/stderr 原文、root 视角对照**；
- 结论边界：只对该机型/内核/场景有效，不得外推；弱证据只写「未观察到」；
- 隐藏规则的下发方式与撤销方式要写明（撤销后需重启）。
