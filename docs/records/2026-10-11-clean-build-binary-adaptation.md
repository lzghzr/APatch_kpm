# 规则：纯净构建 + 二进制适配（2026-10-11）

角色：维护者。来源：用户对开发者的要求（抄送维护者）——**完全按最新版 KP 构建 KPM；源码与 Makefile 不得含任何低版本兼容内容；
低版本兼容只在二进制 `.kpm` 上做修改**。本文把该要求落成流程与身份规则，并**作废**维护者此前与之冲突的请求。

## 一、规则

1. **源码与 Makefile 只面向最新 KernelPatch**：不得出现 `-DCONFIG_KPM_LEGACY` 之类分支、不得为旧内核改动业务实现、
   不得在 Makefile 里放「生成兼容件」的目标或步骤。构建输入集合里也因此**不应出现** `patch_offsets.py` 等兼容工具。
2. **兼容只在二进制产物上做**：对已构建的 `.kpm` 做字节级后处理（如 `patch_offsets.py legacy-kp` 的转接），
   产物是**派生件**，不是「另一个构建变体」。
3. **派生件必须可追溯**：记录 `base instance_id + source_commit + base 产物 sha256 → 变换（工具路径 + 工具 sha256 +
   完整命令）→ 派生件（名称 + sha256 + 大小）`。任何设备证据、验收或交付若使用派生字节，必须同时写明
   base 实例与派生哈希，不得只写其一。
4. **门禁不设兼容要求**：`kp_compat` 为**可选**自识别字段（省略即未声明）；`_legacy` 命名后缀是「可被接受」的机制，
   不是要求；不产出兼容件不影响任何判定。**没有任何门禁条目要求源码或 Makefile 含兼容内容。**
5. **变换要独立复核**：字节级变换会直接改变内核里执行的内容，故当派生物要交付或用于真机结论时，
   变换工具与契约须经独立审计/复核（历史上有过「直接调用跳入数据指针」导致内核 Oops 的记录）。

## 二、作废与取代

- **作废**：[`2026-10-10-zram-zstd-legacy-candidate-request.md`](2026-10-10-zram-zstd-legacy-candidate-request.md)
  中「由 Makefile 增加 legacy 目标、转换必须落在构建事务内、不得先 make 再转接」等要求——它们把临时兼容手段做进了源码/Makefile，
  与本规则冲突。该请求不再对 Developer 有约束力。
- **取代**：需要 4.4 等旧 KP 目标时，先在**纯净源码**上按标准入口构建并登记候选，再对产物做二进制变换得到派生件
  （登记与留证按第一节第 3 条）。

## 三、影响

| 范围 | 说明 |
| --- | --- |
| 已登记的 0.2.0 / 0.3.0 legacy 实例 | 属历史记录，**保持原样不再动**（身份只追加）；其设备证据仍有效但只覆盖当时的字节 |
| 后续构建 | 输入集合不再包含 `patch_offsets.py`；源码树哈希随之变化，产生新的 build_id（正常） |
| 门禁 | 无改动需求；`kp_compat` 已为可选，命名两种形态都接受 |
| 设备侧 | 4.4 目标若需要可加载形态，只能走二进制变换；变换件不是 Release 资产 |

## 四、移除触发条件

KernelPatch 恢复/支持 4.4 兼容后，删除二进制变换路径与相关留证要求；届时 4.4 直接使用标准候选。
