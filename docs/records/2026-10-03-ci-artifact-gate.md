# CI 编译产物检查范围

记录者：维护者。

维护者确定远程 Actions 负责当次编译产物，工程身份与角色交付条件由本地验收门禁核对。
因此将远程检查集中到 Build CI 的构建、产物核验、上传与发布链路，取消单独运行本地仓库门禁的工作流。
本地 `tools/check_repository.py --strict` 的历史输入、产物、报告、验收和交付断言保持原范围。

## 发现与范围调整依据

[失败的 Repository gate](https://github.com/lzghzr/APatch_kpm/actions/runs/37107390204)绑定
`fb40296b754512335b01474417dfca322bcdeae2`，失败项为 `identity_hashes` 与 `version_consistency`。
元数据引用的历史源提交保存在本地历史链，远程重排后的提交链缺少这些对象，导致历史输入读取失败。
[同提交 Build CI](https://github.com/lzghzr/APatch_kpm/actions/runs/37107390229)编译成功。

范围调整由维护者按远程产物职责确定。历史登记和问题状态保留，历史源码核验仍属于本地验收。
现行源码、头文件、Makefile、汇编、构建工具和 KernelPatch 指针变更触发远程构建；文档与报告追加由本地门禁核对。

## 产物检查

- 每个当次选择的模块必须有产物，产物模块集合与构建清单一致。
- KPM 必须为 ELF64 小端 AArch64 ET_REL，节表和内容可读，必需元信息及初始化、退出入口有效。
- ReKernel-X 布局必须与对应 KPM 的 SHA-256、ABI、偏移表范围、字段集合及数值一致。
- 上传前生成提交绑定的清单和 SHA256SUMS；后续作业下载后重算；发布清单对应实际发布文件。

正反回归通过独立构造的 ELF 与布局夹具运行，包含损坏、缺失、越界、架构错误、身份错配、哈希错配及布局错配。
构建检查只证明该工具链能产出通过上述结构和一致性检查的字节；审计与实机结论仍由对应角色报告提供。
