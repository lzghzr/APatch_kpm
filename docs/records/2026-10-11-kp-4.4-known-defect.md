# 外部已知缺陷与临时方案：KernelPatch 0.13.9 × Linux 4.4（2026-10-11）

角色：维护者。触发：用户澄清「`kp_compat` 不应是硬要求，这只是新版 KP 在 4.4 有 bug 的临时方案」。
本文把该事实固定为**外部已知缺陷 + 临时方案**，并明确它不是产品形态、不是交付必需项。

## 一、缺陷（外部组件，不在本仓库修复范围）

| 项 | 内容 |
| --- | --- |
| 组件 | KernelPatch `0.13.9`（本仓库冻结 `b51197aaba8f2272dd8a3e30c85698a29aa928c9`） × Linux 4.4 |
| 现象 | 4.4 内核无法运行当前 KP；设备侧只能跑旧 KP（实测 `d04`，按编码 0.13.4） |
| 连带问题 | 旧 KP 未导出 `kallsyms_lookup_name_by_suffix`，模块加载直接 `unknown symbol` |
| 归属 | KernelPatch 侧；本仓库只能绕过，不能修复 |

## 二、临时方案（`patch_offsets.py legacy-kp`）

- 手段：把 suffix 查找导入转接为旧 KP 可用的原名函数指针跳板（`ADRP`+`LDR`+`BR`）；
  历史上有过「只改导入名称、把直接调用指向数据变量」导致内核 Oops 的记录，现契约已由独立审计复核（0.2.0 审计 §4.3）。
- **定性**：**临时适配，不是产品形态、不是交付必需项、不是门禁硬要求**。
  - 不要求任何模块产出该形态；`kp_compat` 为**可选**自识别字段（省略即未声明），`_legacy` 命名后缀为推荐而非强制；
  - 若为某台 4.4 设备产出，建议登记为独立实例以便身份可追溯，并只随 artifacts 交付、不进 Releases。
- 移除触发条件：**KernelPatch 恢复/支持 4.4 兼容后删除该转接路径**（届时本仓库的 `legacy-kp` 相关约定一并清理）。

## 三、受影响范围

- 仅 4.4（及同样无法运行当前 KP 的旧内核）目标；5.10/5.15+ 不受影响。
- 本模块（zram_zstd）为自有 4.4 测试设备产出过 legacy 实例（0.2.0/0.3.0），其证据保留，
  但**不构成对其它模块的要求**，也不进入 Releases。

## 四、维护者动作

- `metadata/identity.json`：`kp_compat_rule` 改为可选语义；新增 `known_external_defects` 条目 `KP-44-COMPAT`；
- `AGENTS.md`：旧 KP 段由「必须」改为「临时适配、非必需」；
- `tools/artifact_gate.py`：不再要求 `kp_compat` 字段与 `_legacy` 命名互相匹配，两种命名都接受（字段仅作自识别）；
- 后续审计/测试请求不再把 legacy 形态列为必需项。
