# nomount 0.5.1 轮次请求：安全上下文修复的独立审计 → 真机复测（用户主路径）

角色：维护者。**问题来源：用户在 Sony 5.15 实际使用中发现**——注入的系统 APK 已被 PackageManager 登记，但应用与 ART 仍读不到文件。

## 判据更新（维护者，本轮生效）

- [Tester 手册 §4.1](../process/tester-handbook.md)：真机每个目标只测一个变体（release 优先），依据审计的变体差异结论绑定未测变体；

## 致 Auditor

1. **DEV-036 关闭条件**：独立复核 LSM 安全上下文的 ABI、生命周期（是否在正确的时机取得/释放）、初始化独占性与缓存行为，以及 **2 条 Oracle 迁移**；
2. **变体差异**：对本轮 release/debug 逐目标判定差异是否仅限日志/版本串（支撑单变体判据）；
3. **候选与派生件**：独立重编译 4 份候选、独立重跑 16 条目标变换并逐字节比对；
4. 报告按完整 commit + instance_id + 产物 SHA-256 绑定身份。

## 致 Tester（**必须覆盖用户主路径**）

1. **绑定 0.5.1 新身份**，在 **Sony 5.15** 上覆盖**真实应用**：安装注入的系统 APK 后，确认 **artd 与普通应用真的能读取/加载**（`logcat`/`artd` 无 `EACCES`、应用能启动并使用其资源），并给出 dex/资源 mmap 结果；
2. **安全上下文对照**：`Enforcing` 下对照源对象与虚拟对象的 SELinux 标签（`ls -Z`），标签必须一致；
3. **回归 4.4 与 4.19**（同判据、release 变体）；
4. **用户主路径逐条结论**：按 §4.2 列出本轮覆盖的主路径（安装 ZIP → 加规则 → 重启 → 应用真正使用）并写明覆盖/未覆盖；
5. 记录 UID + SELinux 域 + 精确命令 + 原始输出；弱证据只写「未观察到」；
6. **禁止卸载与动态重载**（RA-002）；死机/卡死立即停止并升级。

## 边界

- 6.1 仍无实机；dynamic 形态仍无真机证据；
- 0.5.0 及更早真机结论仍绑定各自实例，不外推到 0.5.1 字节。
