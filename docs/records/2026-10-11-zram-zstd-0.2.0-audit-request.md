## 二、与 0.1.0 的差异（需要独立验证的面）

0.1.0 的审计结论（[报告](../../Auditor/reports/2026-10-10-zram-zstd-module-audit.md)）不自动继承。本轮改动面：

1. **源码子模块**：ZSTD 改用官方 v1.3.1 `contrib/linux-kernel`，声明固定于子模块提交
   `aecf3b479c45affa9fd8ead068e9160253a8ec5c`；兼容头移至模块 `compat/`。
2. **兼容改造**：`zs_btf.c`（BTF 路径）与 `zs_functions.c`（函数推导路径）独立保存两路获取，
   `zs_offsets.c` 保存配置表、调度与公共检查；配置表保留原五项顺序并追加 `driver_name`，**第六项令静态表长为 12 字节**。
3. **legacy 构建路径**：Makefile `legacy` / `legacy_debug` 目标在同一次构建事务内调用
   `patch_offsets.py legacy-kp`（`-DCONFIG_KPM_LEGACY`），产物内嵌 `kp_compat=legacy`。
4. **静态基线产物**：`baselines` / `baselines_debug` 两项偏移仍为模板 `-1`，布局为 12 字节新表。

## 三、要求独立验证的点（按优先级）

1. **子模块输入按冻结 gitlink 核对**：不得以子模块当前 HEAD 或工作区代替冻结提交；核对产物内 codec 字节与
   上游固定源一致、三处地址运算修补、`compat/` 头文件使用是否与实际编译一致。
2. **legacy 转换契约**：两份 legacy 产物中 13 个直接 `CALL26` 是否指向本地转接；原名指针导入的
   `ADRP`/`LDR`/`BR`、重定位与原节保留；无 suffix 导入、短/坏 ELF、多 symtab、重复转接是否被拒绝。
3. **Developer 自检的已知 FAIL 需独立裁定**：`Developer/tools/test_legacy_kp.py`（原 SHA-256
   `cbe4e29e60fe010bfbe2dcbd988cdeffe7b6377dfa94c85caa2991aba2ea022a`）在「要求纯改名」的断言处仍 FAIL，
   Developer 声明这是契约变更所致、未弱化断言、并保留历史 DEV-028 边界。**请给出独立结论**：
   是断言过时还是实现缺陷（不得引用 Developer 的结论作为依据）。
4. **两路获取与停止条件**：BTF 与函数推导的取用顺序、`-ENODATA` 回退条件、必要字段失败即停止；
   名称数组 64／128 字节宽度处理；不得按版本号猜偏移。
5. **产物自识别与命名契约**：`kp_compat`、`offset_mode` 与文件名一致；静态产物的布局与产物表长一致。
6. **沿用 0.1.0 已建立的检查**（可复用方法，但必须重新绑定本次 6 个实例的字节）：独立重编译逐字节比对、
   ELF 节区/重定位自解析、格式检查、Oracle 断言（原 21 项不得弱化）、ASan/UBSan 自检。
