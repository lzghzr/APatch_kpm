## 事实（4.4 实机，Nokia 7 plus，`4.4.192-perf+`，旧 KP `d04`）

- 待测件：动态 legacy-kp 派生件 `971b9e28135bcdfd45c8e223f20d5092ff53e719faaa00f2b08e36f53f5a497b`（base 候选 `7e21475004c69deafa8d32d3607ca5359b0df0907a212ba0bbc37772ea5200ae`）；
- 操作表尺寸**已成功解出** `256/232/128`；
- 随后在 **inode storage 探针有效性检查**处：Nokia 4.4 内核中 **`_etext` 是绝对符号**，其数值**小于**已重定位的 `_stext`，
  使断言 `probe.code_end <= probe.start` **无条件为真** → 报 `inode initial file table evidence unavailable` → `rc=-2` **安全拒载**；
- 模块 fail-closed 干净退出，无崩溃、系统正常启动（安全行为正确，只是判据本身误判）。

## 请求内容

1. **修正符号边界判定**：区分**绝对符号**（如 4.4 的 `_etext`，不参与重定位、数值不可与重定位后的 `_stext` 直接比较）与**重定位符号**；
   或改用不依赖该比较的可核对证据（例如以已确认的函数区间/入口指令序列作为边界依据）；
2. **不得猜偏移、不得放宽 fail-closed**：无法取得可信边界时仍必须停止加载；日志要区分"符号形态不支持"与"区间不可用"；
3. **仅动态路径**：不得影响静态件行为（若静态件字节随之变化，需按 Tester 手册 §4.4 重新取得等价裁定或重测）；
4. **Oracle 纪律**：新增断言单独成文、既有断言不得弱化；
5. **交付**：新的动态候选 + 新的 4.4 legacy-kp 派生件（base 实例、父/子哈希、工具哈希、命令、compat 收据齐备）；
6. **（顺带）`AUD-001`** 仍 open（`key_type` 精确尺寸未解），如本轮可一并处理请给出，否则维持现状。
