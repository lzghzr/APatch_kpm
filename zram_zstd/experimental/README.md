# LZ4KD 原生 16 KiB 窗口实验

`lz4kd16.c` 对一整块 1～16384 字节输入连续查找匹配，使用同一张哈希表，支持跨 4 KiB 边界的回溯。
现有 4 KiB 编解码器和 KPM 注册入口继续使用原实现；本目录只供开发自检与比较。

## 实验块格式 v1

- 首字节固定为 `0x10`。现有普通 4 KiB 格式首字节为 `0x00`，两种解码器分别拒绝另一种标记。
- 后续每个 tag 是 3 字节小端：低 14 位为距离，中间 5 位为重复长度减 4，高 5 位为 literal 长度。
- literal 长度达到 31 时，tag 后追加长度扩展字节，再跟 literal 内容。
- 重复长度达到 35 时，在 literal 内容之后追加长度扩展字节。
- 长度扩展每字节加到基数上，255 表示继续，最后一字节小于 255；恰好达到基数也追加一个 0。
- 距离为 0 的 tag 是终结 literal：literal 必须非空、重复长度必须为 4，内容结束即块尾。
  最后一个匹配也可以直接结束整块。调用方提供输入长度、输出容量及预期解压大小。

该实验格式由本项目定义。它不是上游普通 4 KiB 格式的可互换字节流。

## 内存与失败行为

沿用固定上游的 4096 槽、16 位位置哈希表、两次探针和自适应 skip；前进前先核对真实输入余量。
tag 输出为精确有界写入，匹配延伸使用有界 8 字节读取和字节尾处理。
不压缩的数据生成同一实验格式的 literal-only 块，16384 字节的最大输出为 16453 字节。

每个压缩上下文占 24646 字节：8192 字节哈希表、16453 字节 scratch，加 1 字节结构尾部对齐。
上下文由调用方预先分配并复用，热路径不分配内存。压缩容量不足时不改变输出缓冲区或 `dlen`；
解压失败保留 `dlen`，但输出可能已被部分写入。输入与输出不得重叠。

## 复现测试

在仓库根目录运行，需要 ARM64 macOS、Android NDK Clang、macOS SDK；每次使用新的输出目录：

```sh
python3 Developer/tools/test_lz4kd16.py --clang "$NDK_CLANG" --sdk "$(xcrun --show-sdk-path)" \
  --output local/lz4kd16-experiment-01
```

默认要求实验输入已提交；`--allow-dirty` 仅用于探索。脚本产出绑定提交、实验实例和产物 SHA-256 的 `results.json`：

1. ASan/UBSan：全部 1～16384 字节、四类数据、精确/不足容量、长距离向量、截断及畸形流。
2. Android ARM64 对象：使用 KPM 的标量寄存器约束，完整反汇编检查 FP/SIMD/SVE/x18 和未解码指令。
3. 同一 NDK 的 ARM64 macOS 对照：原生 16 KiB、四个普通 4 KiB 块、LZ4、原生参数 ZSTD。
   codec 和包装层使用 KPM 标量约束；计时驱动独立编译，遵循宿主浮点 ABI。

每类语料 64 页，每页 16 KiB；源码文本、整数、带空洞二进制、随机数据分开报告。
4 KiB／8 KiB 随机片段重复页面作为远距离匹配的阳性对照，单独报告。
四块封装计入 10 字节头和长度表；导出文件的逐页 4 字节测试记录长度不计入各算法输出。
Python 逐字节参考解析器另行还原两种 LZ4KD 输出，并记录实际使用的最大匹配距离。

这些结果用于判断扩展价值。Crypto API 接入、16 KiB 内核 zram、并发回收与 Android 设备吞吐由后续独立审计和真机测试覆盖。
