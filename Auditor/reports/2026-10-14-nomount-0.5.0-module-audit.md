## 3. 本轮演进改动深度审计

### 3.1 查找性能优化（0.4.2 引入）

- **UID 256-bit 掩码快速预筛选**：在 `struct nm_uid_array` 中增加 `u64 bloom_mask[4]`。`nomount_is_uid_blocked(uid)` 检查时先做 `nm_uid_bloom_test(array, uid)` 位测试，未命中直接返回 `false`，命中后再做精确循环比对；UID 删除时重新扫描并重建掩码；
- **小目录快速查找**：当 `count <= 2` 时 `nm_bloom_words_for` 返回 `0`，跳过大 Bloom 表分配与名字完整哈希，改用 `nm_qhash`（首末字节异或及位移快速匹配）与精确比对；二分查找外提 `entries` 指针；
- **安全性评估**：位测试只作为快速短路（不会产生假阴性漏拦截，假阳性也会被后续精确比对过滤），数组构造在发布前完成并受 RCU 保护，**无并发竞争或安全漏洞**。

### 3.2 私有小对象分配优化（0.4.3 引入）

- **双级内存分配器（`nomount/nm_memory.c`）**：
  - `nm_zalloc(size)`：对于 `size <= 1024` 的小对象（如 `nm_inode_info`、规则节点），按 64 字节二次幂对齐向上取整，调用原生 `__kmalloc(span, 0)` 分配并清零。若 slab 分配失败或 `size > 1024`，回退至 `vzalloc(size)`；
  - `nm_free(ptr)`：统一调用原生 `kvfree(ptr)`，自动区分 slab 与 vmalloc；
  - `nm_free_rcu(ptr)`：在 RCU 回调上下文释放时，通过 `is_vmalloc_addr(ptr)` 判断，vmalloc 地址走 `vfree_atomic(ptr)`（避免原子上下文睡眠），slab 地址走 `kfree(ptr)`。
- **安全性与稳定性评估**：
  - `__kmalloc` 传入 `flags = 0`，代表非阻塞原子分配，绝不进入睡眠调度或跨版本 GFP 宏不兼容陷阱；
  - RCU 释放显式分流 `vfree_atomic`，杜绝了直接调用 `vfree` 导致的内核 Panic；
  - 原生符号 `__kmalloc`、`kvfree`、`is_vmalloc_addr`、`vfree_atomic` 在 4.4 至 6.1 内核中均有原生导出，符号解析具备跨版本稳定性。

### 3.3 Inode 与管理规则彻底解耦（0.5.0 核心重构）

- **重构动因**：此前 `struct nm_inode_info` 持有 `struct nomount_rule* rule` 裸指针，inode 依赖管理规则对象的生命周期。若后续支持规则动态注销，存活的 VFS inode 解引用规则会触发悬挂指针（UAF）。
- **解耦设计**：
  1. `struct nm_inode_info` 彻底移除 `struct nomount_rule* rule` 字段，改为直接内联 `struct nm_path r_path`、`void* dir_node`、`u16 flags`、`bool initialized`；
  2. 物化 inode 时（`nm_materialize_file` / `nm_cached_directory_get`），调用 `nm_bind_inode_path` 拷贝 `r_path`，并显式执行原生 `path_get(&info->r_path)` 增加目标路径引用计数；
  3. 回收释放时（`nm_proxy_evict_inode`），在进程上下文执行 `nm_put_inode_binding`，显式调用 `path_put(&info->r_path)` 并归还 `dir_node` 引用；RCU 延迟释放只负责释放 `info` 内存结构；
  4. 目录 Inode 散列由旧的按 `rule` 散列迁移为按 `dir_node` 散列，匹配时校验 `initialized`（原子加载）及 `i_mode`/`i_uid`/`i_gid`。
- **20 处 Oracle 测试断言迁移复核**：
  - Auditor 逐项走查 Developer 在自检中调整的 20 处 Oracle 断言：
    - 断言 38、164、169、193、399：确认 `rule->refs` 由 2 降为 1（因 inode 不再持有 rule 的引用，符合解耦预期）；
    - 断言 44、45、199：确认规则被管理层释放后，inode 仍安全持有独立的 `r_path`（`path_puts` 计数增加）；
    - 断言 126、362：确认散列由 `rule` 改为 `dir_node`；
    - 其余断言：确认由 `info->rule->r_path` 变更为直接访问 `info->r_path`。
  - **复核结论**：断言变更完全是生产代码架构解耦的真实映射，未放宽边界检查，未掩盖任何缺陷。

## 4. 上游 v2.1.1 未移植项最新状态评估

在经过 0.4.2（查找优化）与 0.5.0（Inode 绑定解耦）之后，对比上游 master (`7046c7ad…`)，KPM 仅余两项未移植重构：
1. **规则数组与字符串内联紧凑打包 (`d5955a2`)**：上游 LKM 将字符串直接拼接在规则数组末尾。KPM 当前规则采用链表+不可变指针数组，由启动期一次性分配常驻，无频繁增删碎片，不影响功能；
2. **整批 ADD 管理锁覆盖 (`1f35f82`)**：上游将锁提至整批处理最外层。KPM 在锁外进行路径预解析、持锁短时发布的机制，能有效避免在复杂 VFS 回调中锁重入。
- **评估结论**：剩余两项属于上游 LKM 特定的内存布局与锁粒度调整，**不含任何关键安全性或正确性 Bugfix**。KPM 0.5.0 架构严谨完整。
