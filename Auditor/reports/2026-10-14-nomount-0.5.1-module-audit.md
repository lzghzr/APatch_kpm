## 3. DEV-036 缺陷独立复核与架构安全审计

### 3.1 缺陷成因与现场机理（Sony 5.15）

- **现象**：在 Enforcing 模式下，用户将系统 APK 注入到虚拟目录后，`PackageManager` 虽能登记该包，但随后的 ART 编译引擎（`artd`）及普通用户应用在尝试读取/加载注入的 APK 时均返回 `EACCES` (Permission denied)，导致类加载抛出 `ClassNotFoundException`。
- **成因定位**：0.5.0 及更早版本物化虚拟 Inode 时，仅复制了 Linux VFS 基本属性（`i_mode`、`i_uid`、`i_gid` 等），**未为新生成的虚拟 inode 初始化原生 LSM 安全上下文（Security Inode Context）**。在后续进行文件 `mmap` 时，KPM 清除了 `S_PRIVATE` 标志以兼容原版映射契约，使得 Linux 安全子系统（SELinux）对该 Inode 执行标准 AVC 检查。由于缺少安全标签，虚拟 inode 被默认为 `unlabeled`（未标记），SELinux 策略直接拒绝了 `artd` 和普通应用域对 `unlabeled` 文件的读取操作。此前 Tester 的测试探针运行于 `magisk` 域，具有对 `unlabeled` 对象的宽泛豁免权，因而掩盖了该缺陷。

### 3.2 原生 LSM ABI 合规性审查（`nomount/nm_security.c`）

Auditor 独立走查 Linux 内核在 4.4、4.19、5.10、5.15 与 6.1 下的原生 LSM 接口规范：

1. **`security_inode_getsecctx(struct inode *inode, void **ctx, u32 *ctxlen)`**：
   - 从源 Inode 获取 SELinux 上下文字符串及其长度，LSM 内部通过 `kmemdup`/`kstrdup` 动态分配上下文缓冲区；
   - **调用时机与上下文检查**：该函数内部可能发生内存分配与睡眠，**严禁在原子上下文或持有自旋锁/RCU 读锁时调用**。在 `nm_materialize_file` 与 `nm_materialize_virtual_directory` 中，`nm_get_security_context` 均在最外层（函数入口处）执行，处于非原子进程上下文，未持有任何 iget 锁、hash 锁或模块 RCU 锁，符合内核调度安全契约。
2. **`security_inode_notifysecctx(struct inode *inode, void *ctx, u32 ctxlen)`**：
   - 将上下文字符串转换并写入目标 Inode 的 LSM 私有 blob（通过 `inode_doinit_with_dentry`）；
   - **初始化顺序约束**：LSM 依赖 `inode->i_mode` 确定对象类别（文件、目录、符号链接等）。在 `nm_materialize_file` 中，`nm_initialize_file_inode` 先行写入源文件的 `i_mode`；在 `nm_materialize_virtual_directory` 中，`nm_initialize_directory_inode` 先行写入目录的 `i_mode`。在此之后才调用 `nm_initialize_inode_security`，对象类型判定完全准确。
3. **`security_release_secctx(char *secdata, u32 seclen)`**：
   - 释放 LSM 内部为上下文分配的缓冲区；
   - 在 `nm_materialize_file` 与 `nm_materialize_virtual_directory` 的所有正常与异常退出分支中，均无条件调用 `nm_release_security_context`，不存在上下文内存泄漏。
4. **`security_inode_getsecid(struct inode *inode, u32 *secid)`**：
   - 非分配、非睡眠接口，直接读取 Inode 已分配的 SID；
   - 用于在 `notifysecctx` 完成后，验证目标 Inode 的 SID 是否确实与源 Inode 的 `secid` 一致（`nm_inode_secid(inode) != context->secid` 则判定失败返回 `-EACCES`），杜绝了某些不支持标签的 LSM 伪成功返回 0 却导致对象处于 `unlabeled` 的静默降级风险。

### 3.3 生命周期、独占性与失败回滚审查

1. **普通文件物化独占性与失败清理**：
   - 普通文件 Inode 在创建期间由 Materializer 线程私有持有，尚未通过 `d_splice_alias` 发布给 VFS；
   - 若 `nm_initialize_inode_security` 返回失败，立即执行 `kfunc(nm_iput)(inode)`。此时 Inode 引用计数降为 0，触发原生 `evict` -> `nm_proxy_evict_inode` -> `nm_put_inode_binding`（归还 `r_path` 引用）-> `nm_free(info)`，全部独立绑定与 LSM blob 被原生安全回收，返回 `ERR_PTR(rc)`，无任何脏状态暴露。
2. **虚拟目录 `I_NEW` 独占并发控制与等待者清理**：
   - 虚拟目录 Inode 通过 `nm_iget5_locked` 创建，原生 VFS 自动置位 `I_NEW`，阻挡所有并发查找该 Inode 的线程进入 `wait_on_inode` 等待队列；
   - 初始构造者在 `I_NEW` 保护下完成 `i_mode` 设定并执行 `nm_initialize_inode_security`，将结果写入 `info->init_error`，原子设置 `initialized = true` 后调用 `unlock_new_inode` 唤醒等待者；
   - **唤醒者错误闭环**：无论是初始构造者还是被唤醒的等待者，在取得 Inode 后均无条件检查 `existing->init_error`。一旦发现初始化错误，**绝不调用 `d_splice_alias` 发布 alias**，而是立即调用 `iput(inode)` 并返回错误码。同时在 `nm_inode_matches_binding` 中增加 `if (info->init_error) return false;`，确保后续查找绝不会命中该失败 Inode。
3. **标签变更动态缓存失效**：
   - `struct nm_inode_info` 中新增 `u32 secid` 字段；
   - 目录缓存匹配 `nm_cached_directory_test` 与目录项重验证 `nm_dentry_validate` 均核对来源对象实时的 `nm_inode_secid` 与 `info->secid`；
   - 若源对象在运行时发生 SELinux 重标记（relabel/restorecon），缓存比较因 SID 不匹配而立即失效，强制丢弃旧 Inode 并重新物化，确保安全标签始终与源对象强一致。
