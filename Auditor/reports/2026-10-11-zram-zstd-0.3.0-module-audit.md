## 3. 结论摘要

- **独立复现通过的检查**：
  - **普通候选独立重编译**：4 份普通产物 SHA-256 及 2 份配套布局 JSON 与在册记录 **100% 逐字节吻合**；
  - **二进制派生件独立复现**：以普通候选为输入独立执行 `legacy-kp` 变换，产物 SHA-256（`2cd50444...` 与 `20af1b9b...`）及回执与在册记录 **100% 逐字节吻合**；
  - **节区与重定位**：4 份普通候选与 2 份派生件必需节区 `.kpm.info`、`.kpm.init`、`.kpm.ctl0`、`.kpm.exit` 齐备（8 字节入口），入口重定位（`R_AARCH64_ABS64`）合法；
  - **静态布局契约**：两份 `baselines*` 的 `.kpm.json` 为 schema 3，对应配置表节大小为 12 字节（6 项 `int16_t`）；偏移均为模板值 `-1`，未声称可直接加载；
  - **变换契约与安全**：派生件内原本调用 `kallsyms_lookup_name_by_suffix` 的 **13 处直接 `CALL26` 重定位**，在派生产物中全部安全解析至本地 `.text.kpm_legacy_lookup` 跳板（12 字节 ADRP+LDR+BR x16），正确解引用原名数据指针 `kallsyms_lookup_name`，根除历史 Oops 隐患；
  - **输入保护与异常拒绝**：`legacy-kp` 对重复转换、非 ELF 损坏文件、缺失未定义后缀符号的 ELF 均有确切错误拦截并返回非零，异常保护完备；
  - **上游源码冻结**：ZSTD 1.5.7-kernel 子模块准确固定于 `5d9fb4785030731a155a8abe159e10965d824e4b`；`SOURCES.json` 95 份原始源文件逐字节核对零漂移；`prepare_codec.py` 使用上游官方 `freestanding.py` 工具生成内核兼容源，未发生未授权篡改；

### 4.3 派生 ELF 结构与安全跳板契约解析

Auditor 自解析派生 ELF 文件：
1. **节区与修改范围**：
   - 原始二进制前 507,984 字节除 ELF Header 中的 `e_shoff`（偏移 40，大小 8）与 `e_shnum`（偏移 60，大小 2）被更新外，既有代码段与数据段完全保持不变；
   - 派生追加内容紧随末尾（从偏移 507,984 开始追加 34,512 字节），包含更新后的符号串表、符号表、新增节区 `.text.kpm_legacy_lookup`（大小 12 字节）、重定位节区 `.rela.text.kpm_legacy_lookup`（大小 48 字节）以及节区头表；
2. **跳板指令实现**：
   - ELF 节区 `.text.kpm_legacy_lookup` 包含 3 条 32 位 AArch64 指令：
     ```arm64
     0x90000010 : adrp x16, kallsyms_lookup_name        ; R_AARCH64_ADR_PREL_PG_HI21
     0xf9400210 : ldr  x16, [x16, :lo12:kallsyms_lookup_name] ; R_AARCH64_LDST64_ABS_LO12_NC
     0xd61f0200 : br   x16
     ```
3. **调用点安全重定向**：
   - 在符号表中，`kallsyms_lookup_name_by_suffix` 由原本未定义的导入函数（SHN_UNDEF）被重新定义为位于 `.text.kpm_legacy_lookup` 节区起始处的局部函数（`st_shndx=23`, `st_size=12`）；
   - 未定义符号表中仅追加导入数据指针 `kallsyms_lookup_name`（`st_shndx=SHN_UNDEF`, `st_info=STB_GLOBAL|STT_OBJECT`）；
   - 产物代码段中原有的 **13 处直接 `R_AARCH64_CALL26` 重定位**符号索引保持不变，因此在模块加载链接时，这 13 处直接调用均天然解析至该本地跳板函数，而不会跳向数据指针本身；
   - 该机制彻底根除了低版本内核上因直接跳转数据指针导致的指令异常（Oops）。

### 4.4 变换工具异常保护与负向测试

Auditor 对 `patch_offsets.py legacy-kp` 实施独立负向测试：
1. **重复转换拦截**：以已转换的派生产物为输入再次执行 `legacy-kp`，工具立即检测到缺失全局未定义后缀符号并退出：
   `error: lookup adapter requires undefined global imports in the same symbol table`（返回非零，通过）；
2. **坏 ELF 文件拦截**：以畸形文件为输入，工具检测 ELF 魔数并退出：
   `error: expected ELF64 little-endian KPM`（返回非零，通过）；
3. **缺失后缀查找符号拦截**：以不含 `kallsyms_lookup_name_by_suffix` 导入的合法 ELF 为输入，工具拒绝转换并报错（返回非零，通过）；
4. **输出覆盖保护**：目标输出文件或回执已存在时，工具报错 `FileExistsError` 并回滚未完成写入，防止覆盖既有资产。

- **结论**：未发现缓冲区溢出、未初始化使用、非法内存解引用等阻塞性缺陷。
