## 1. 问题背景与关闭条件核对

### 1.1 问题简述
在 Sony Xperia 1 V（Linux 5.15，Android 15，SELinux `Enforcing`）真机上，用户将系统 APK 注入到虚拟目录后，虽然 `PackageManager` 能扫描登记该应用，但后续 ART 编译守护进程（`artd`）与受限应用进程读取虚拟 APK 时均返回 `EACCES`，导致类加载失败抛出 `ClassNotFoundException`。  
根本原因为：0.5.0 及更早版本物化虚拟 Inode 时未初始化原生 LSM 安全上下文，且在 `mmap` 后清除了 `S_PRIVATE`，使得 SELinux 面对未标记（`unlabeled`）的 Inode，从而拦截了受限域的读取请求。

### 1.2 问题单规定的闭环条件（`closure`）
> 「Auditor 独立复核 LSM ABI/生命周期/初始化独占/缓存及 2 条 Oracle 迁移，Tester 绑定 0.5.1 新身份覆盖 Sony 5.15 真实应用和 artd 读取/DEX 加载并回归 4.4、4.19 后，由独立于 Developer 的角色复核关闭。」

Auditor 作为独立于归属方（`owner=Developer`）的角色，对两部分证据开展全面独立复核。

## 2. Auditor 侧代码与架构独立复核

在模块独立审计报告 [`Auditor/reports/2026-10-14-nomount-0.5.1-module-audit.md`](../2026-10-14-nomount-0.5.1-module-audit.md) §3 中，Auditor 已完成深层静态分析与架构复核：

1. **原生 LSM ABI 合规性**：
   - `security_inode_getsecctx`：在 `nm_materialize_file` 与 `nm_materialize_virtual_directory` 入口处（锁外、非原子上下文）执行，满足 Linux 内核内存分配与睡眠调度要求；
   - `security_inode_notifysecctx`：在目标 Inode 写入 `i_mode` 后调用，确保 LSM 准确识别对象类型（S_IFREG/S_IFDIR）；
   - `security_release_secctx`：在所有正常与异常路径中成对释放上下文内存，无内存泄漏；
   - `security_inode_getsecid`：非睡眠接口读取已分配 SID，用于核对 `notifysecctx` 后的实际 SID（`nm_inode_secid(inode) != context->secid` 返回 `-EACCES`），防止不支持标签的 LSM 伪成功返回 0 导致静默降级为 `unlabeled`。
2. **生命周期与错误回滚**：
   - 普通文件物化失败调用 `kfunc(nm_iput)(inode)`，触发原生 `evict` 回收 `r_path` 引用及 LSM blob；
   - 虚拟目录物化由 `I_NEW` 锁保护初始构造过程；构造失败将错误码记录于 `info->init_error`，唤醒等待者无条件核对该错误码并安全调用 `iput`，绝不向 VFS 发布错误 alias；
   - `nm_inode_matches_binding` 增加 `if (info->init_error) return false;`，杜绝后续查找命中失败 Inode。
3. **动态标签感知与缓存失效**：
   - `struct nm_inode_info` 记录物化时来源的 `secid`；
   - 目录缓存匹配 `nm_cached_directory_test` 与目录项重验证 `nm_dentry_validate` 均核对实时来源 SID；源对象在运行时发生 `relabel` / `restorecon` 时，缓存即刻失效并重新物化。
4. **Oracle 断言迁移合规性**：
   - 原 735 条旧断言中，733 条保持原表达式、顺序与判定完全一致；
   - 仅 2 条断言因 `nm_inode_matches_binding` 追加 `u32 secid` 参数而传入 fixture SID (`1`)，未放宽或删除任何检查条件；
   - 新增 51 条覆盖错误分支与安全生命周期的专属测试断言，并在 ASan/UBSan 下通过。
