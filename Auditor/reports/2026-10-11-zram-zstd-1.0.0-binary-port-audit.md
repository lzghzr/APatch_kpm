## 3. 详细审计与独立技术分析

### 3.1 二进制派生件独立变换与复算

依据仓库干净构建规范，Makefile 与源码仅面向现代 KernelPatch，不含旧版兼容编译分支。针对 Android 4.4 等未导出 `kallsyms_lookup_name_by_suffix` 的旧目标，由 Developer 随候选交接提供基于 `patch_offsets.py legacy-kp` 的二进制变换派生件。

Auditor 在隔离沙箱 `local/auditor-scratch/v1.0.0/binary-port` 下以独立重编译的基准候选为输入，独立执行变换：
```bash
python3 patch_offsets.py legacy-kp \
  local/auditor-scratch/v1.0.0/worktree/zram_zstd/zram_zstd_1.0.0.kpm \
  --output local/auditor-scratch/v1.0.0/binary-port/zram_zstd_1.0.0.kpm

python3 patch_offsets.py legacy-kp \
  local/auditor-scratch/v1.0.0/worktree/zram_zstd/zram_zstd_1.0.0_debug.kpm \
  --output local/auditor-scratch/v1.0.0/binary-port/zram_zstd_1.0.0_debug.kpm
```

比对结果：
- **Release 派生产物**：沙箱独立变换 SHA-256 为 `e829df670157a8024484e16840858f07b3613ec292b252d5c1b89333e3ca535c`，大小 548,912 B，与在册归档产物逐字节完全一致（MATCH）；
- **Debug 派生产物**：沙箱独立变换 SHA-256 为 `75a124a68c569bcad1bba97d3a906daea0dc04bed1abefaa37948d46c88fb7fd`，大小 548,920 B，与在册归档产物逐字节完全一致（MATCH）；
- **回执文件比对**：两份产物的 `.compat.json` 回执哈希（`32da113b...` 与 `e520eaaf...`）与在册归档回执完全一致（MATCH）。

### 3.2 派生 ELF 结构与跳板机制独立解析

Auditor 对派生产物执行独立 ELF 字节解析：
1. **基准内容保护与节区扩展**：
   - ELF 文件前 513,616 字节（Debug 为 513,624 字节）除 ELF Header 中的 `e_shoff`（偏移 40，大小 8）与 `e_shnum`（偏移 60，大小 2，由 23 扩展至 25）被更新外，其余原有代码段、数据段、BTF 结构及 `.kpm.*` 控制元数据节区内容**绝对零修改**；
   - 派生追加内容紧随文件末尾（追加 35,296 字节），包含新增代码节区 `.text.kpm_legacy_lookup`（大小 12 字节）、重定位节区 `.rela.text.kpm_legacy_lookup`（大小 48 字节）以及重新排版的符号表与节区头表；
2. **跳板指令实现**：
   - 节区 `.text.kpm_legacy_lookup` 包含 3 条 32 位 AArch64 指令：
     ```arm64
     0x90000010 : adrp x16, kallsyms_lookup_name
     0xf9400210 : ldr  x16, [x16, :lo12:kallsyms_lookup_name]
     0xd61f0200 : br   x16
     ```
   - 重定位表 `.rela.text.kpm_legacy_lookup` 包含 2 处重定位：
     - 偏移 `0x0`: `R_AARCH64_ADR_PREL_PG_HI21`，符号 `kallsyms_lookup_name`，addend `0`；
     - 偏移 `0x4`: `R_AARCH64_LDST64_ABS_LO12_NC`，符号 `kallsyms_lookup_name`，addend `0`；
3. **符号重定义与链接安全性**：
   - 符号 `kallsyms_lookup_name_by_suffix` 由原本的未定义函数（`SHN_UNDEF`）被重定义为位于本地节区 `.text.kpm_legacy_lookup` 起始处的全局函数（`STB_GLOBAL|STT_FUNC`，大小 12，值 `0x0`）；
   - 未定义符号表中仅追加导入数据指针 `kallsyms_lookup_name`（`STB_GLOBAL|STT_OBJECT`，`SHN_UNDEF`）；
   - 旧版 KernelPatch 4.4 导出数据指针 `kallsyms_lookup_name`，模块加载器在链接跳板重定位时，将指针地址填入跳板的 ADRP/LDR 指令；
   - 模块代码调用该函数时，AArch64 调用规范首参寄存器 `x0`（待查符号名字符串）保持不变，跳板加载内核函数指针并直接 `br x16` 跳转，返回值经 `x0` 返回，调用语义完全透明等价。

### 3.3 CALL26 调用点核验与 0.3.0 差异来源分析

维护者在审计请求 [`docs/records/2026-10-11-zram-zstd-1.0.0-port-audit-request.md`](../../docs/records/2026-10-11-zram-zstd-1.0.0-port-audit-request.md) 中提及「独立判断 13 处 CALL26 跳板」。

**Auditor 关键事实纠偏与独立核实**：
1. **调用点数量**：13 处为 0.3.0 轮次的调用点数量；在 1.0.0 基准产物中，Auditor 独立解得 targeting `kallsyms_lookup_name_by_suffix` 的 `R_AARCH64_CALL26` 重定位**实际为 23 处**（Release 与 Debug 均为 23 处）。
2. **分布位置与函数映射**：
   - `zram_zstd_init` 内包含 **16 处**调用（偏移 `0x4c`, `0xb8`, `0xcc`, `0xe0`, `0x110`, `0x124`, `0x138`, `0x14c`, `0x160`, `0x23c`, `0x2a0`, `0x2b0`, `0x468`, `0x518`, `0x5a8`, `0x5b8`）；
   - `start_zram_display` 内包含 **6 处**调用（偏移 `0xfec`, `0x1000`, `0x1014`, `0x1028`, `0x103c`, `0x1074`）；
   - `install_zram_display` 内包含 **1 处**调用（偏移 `0x1d20`）。
3. **差异来源**：
   - 1.0.0 相较于 0.3.0 新增了 `zs_display.c` 实现（sysfs 压缩算法展示支持），需要通过动态符号解析获取 `module_mutex`、`mutex_lock`、`mutex_unlock`、`__module_text_address`、`core_kernel_text`、`do_init_module` 与 `zcomp_available_show`；
4. **适配风险与健壮性评估**：
   - 派生变换工具 `patch_offsets.py legacy-kp` 基于符号名全局索引重定义，所有 23 处 CALL26 重定位的符号索引均无遗漏地指向本地跳板节区，因此 23 处调用无一遗漏地安全解析至跳板；
   - 代码健壮性检查：走查 `zs_display.c`，所有通过 `kallsyms_lookup_name_by_suffix` 获取的函数/对象指针均有严格的空指针保护（第 48-63 行、74-88 行），若 4.4 内核缺失某辅助符号，模块将安全记录日志退出 display hook 流程，不会触发内核 Oops；
   - 真机事实背书：Tester 在 Nokia 7 plus（4.4.192）上的开机引导嵌入测试（`Tester/reports/runs/2026-10-11-zram_zstd-1.0.0-4.4-boot-live#1.md`）实证表明：1.0.0 成功完成 hook，在未激活状态下成功于 `/sys/block/zram0/comp_algorithm` 显示 `zstd-kpm`，12/12 强判据全部通过，运行稳定。
   - **结论**：1.0.0 二进制派生件未引入新的适配风险。

### 3.4 变换工具异常保护与负向测试

Auditor 在沙箱中对 `patch_offsets.py legacy-kp` 执行独立负向测试：
1. **重复转换拦截**：以已派生的产物再次输入，工具检测到无未定义后缀符号并退出：
   `error: lookup adapter requires undefined global imports in the same symbol table`（返回码 1，通过）；
2. **坏 ELF 文件拦截**：以非 ELF 格式畸形文件输入，工具检测魔数并退出：
   `error: expected ELF64 little-endian KPM`（返回码 1，通过）；
3. **输出覆盖保护**：以已存在的派生文件为目标输出，工具拒绝覆写既有产物：
   `error: output KPM or receipt/layout already exists; choose a new path`（返回码 1，通过）。

## 4. MNT-018 独立复核与关闭裁决

### 4.1 问题单背景

问题单 `MNT-018` 指出：0.3.0 验收引用了 `RA-001`，但 `RA-001.approval_scope` 仅批准了 0.1.0 的 8 个候选，存在风险接受范围与验收引用不一致的问题。

### 4.2 维护者整改与用户授权复核

Auditor 独立审查 `metadata/modules/zram_zstd.json` 与维护者回应 [`docs/records/2026-10-11-MNT-017-018-response.md`](../../docs/records/2026-10-11-MNT-017-018-response.md)：
1. **原文保护**：`risk_acceptances[RA-001].approval_scope` 与两次破坏性验证实证记录（`revision`）原文完整保留，未被篡改；
2. **追加扩展数组**：新增 `scope_extensions[]` 包含 3 项明确扩展：
   - **0.3.0 扩展**：覆盖 4 个候选长实例 ID、2 份派生件 SHA-256（`2cd50444...`, `20af1b9b...`），绑定 Nokia 7 plus（4.4.192），记录 `approved_by: "用户"`；
   - **0.4.0 扩展**：覆盖 4 个候选长实例 ID，绑定 Sony Xperia 1 V（5.15.189 GKI），记录 `approved_by: "用户"`；
   - **1.0.0 扩展**：覆盖 4 个候选长实例 ID、2 份派生件 SHA-256（`e829df67...`, `75a124a6...`），绑定 Nokia 7 plus（4.4.192）与 5.15 GKI，记录 `approved_by: "用户"`；
3. **约束明确**：所有扩展均明确约定「常驻使用：开机嵌入加载；禁止卸载与动态重载；唯一移除方式为撤销嵌入配置后重启」；
4. **验收引用自洽**：1.0.0 模块的全部 4 条验收记录（`acceptances[]`）均已规范标注 `risk_acceptances: ["RA-001"]`。

### 4.3 裁决结论

`MNT-018` 预设的所有关闭条件（独立确认覆盖本轮具体实例与派生哈希、KP/设备与常驻限制、批准来源可追溯、验收引用一致）均已齐备并通过核验。

**裁决：MNT-018 复核通过，予以关闭（CLOSED）。**  
（注：元数据状态字段由维护者同步更新）。

*关于 MNT-017 状态*：仍维持 **OPEN**，待维护者与用户完成交付提交 D（用户签名）、逐实例绑定与回执 E 闭环后，由 Auditor 或 Developer 复核关闭。

## 5. 同源风险与未验证声明

1. **同源风险声明**：
   - 变换工具 `patch_offsets.py` 归属于开发者维护代码，存在构建链同源风险；
   - Auditor 通过在隔离沙箱中独立重跑变换、基于独立 Python 脚本逆向解析 ELF 节区与重定位、逐条反汇编验证跳板机器码、以及独立设计负向防御测试用例，从外部黑盒与字节白盒双重层面切断同源依赖，同源风险已有效消除。
2. **未验证声明**：
   - 派生件的实机验证目前仅在 Nokia 7 plus（`Linux 4.4.192-perf+`）设备上通过 12/12 项强证据判定；
   - 鉴于当前测试机群中 Android 4.9/4.14 真实设备离线，派生件在其他非 4.4 旧内核版本上的引导表现属于**未验证**；
   - Android 5.15+ GKI 内核原生导出后缀查找符号，无需且不得加载此类派生件。

## 6. 审计结论

1. Developer 交接的 2 份 `zram_zstd` 1.0.0 二进制派生件（Release 与 Debug）经沙箱独立变换重算，SHA-256 与回执哈希 **100% 逐字节吻合**；
2. 派生 ELF 头部修改合规，跳板指令架构正确，**23 处 CALL26 调用点全量安全重定向**至本地跳板函数，未引入任何新兼容风险；
3. `MNT-018` 范围扩展与用户授权核验通过，**予以关闭**；`MNT-017` 维持 **OPEN**。
