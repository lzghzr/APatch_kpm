### 4.3 legacy 转换契约独立解析

在 Android 4.4 等低版本内核上，KernelPatch 仅导出数据指针 `kallsyms_lookup_name`，未导出可直接 `BL` 的函数符号 `kallsyms_lookup_name_by_suffix`。

Auditor 自解析两份 legacy 产物（`zram_zstd_0.2.0_legacy.kpm` 与 `zram_zstd_0.2.0_legacy_debug.kpm`）：
1. **未定义符号表**：`kallsyms_lookup_name_by_suffix` 已不再作为 undefined symbol 导入；而 `kallsyms_lookup_name` 正式作为 undefined symbol（数据指针）导入。
2. **转接跳板节区**：ELF 中新增节区 `.text.kpm_legacy_lookup`（大小 12 字节），包含 3 条指令：
   ```arm64
   adrp x16, kallsyms_lookup_name        ; R_AARCH64_ADR_PREL_PG_HI21
   ldr  x16, [x16, :lo12:kallsyms_lookup_name] ; R_AARCH64_LDST64_ABS_LO12_NC
   br   x16
   ```
3. **调用点重定向**：产物中原本调用 `kallsyms_lookup_name_by_suffix` 的 **13 处直接 `R_AARCH64_CALL26` 重定位**，全部准确指向该局部跳板函数符号。
4. **结论**：转换契约严格保证直接调用跳转到代码执行，指针解引用正确，根除了历史曾经发生过的“直接调用跳入数据指针导致内核 Oops”的隐患。

### 4.4 Developer 自检 FAIL（`test_legacy_kp.py:82`）独立裁定

Developer 在自检收据中声明 `Developer/tools/test_legacy_kp.py` 仍存在 FAIL，并作为 Oracle 保留。

Auditor 独立审查该用例的断言逻辑：
- `test_legacy_kp.py:82` 包含断言：
  ```python
  assert new_symbols == [(NEW if name == OLD else name, info, index) for name, info, index in old_symbols]
  ```
  该断言假设旧的 naive 转换模式（仅仅将 undefined symbol 名从 `kallsyms_lookup_name_by_suffix` 替换为 `kallsyms_lookup_name`）。
- **技术裁定**：旧的 naive 模式在 AArch64 ABI 下是不安全的——当被调用符号是数据指针时，直接 `BL` 会跳到数据内存中导致指令异常（Oops）。当前 `patch_offsets.py legacy-kp` 采用的跳板（stub）方案将该符号在内部定义为函数跳板，符合内核模块安全规范。
- **结论**：`test_legacy_kp.py:82` 的 FAIL 属于**测试用例断言过时**（反映已被废弃的不安全历史契约），**不构成生产实现缺陷**。Developer 遵循 Oracle 规则未私自改动断言，并在新用例（`test_legacy_kp_adapter.py` / `test_zram_legacy.py`）中覆盖了正确契约，裁定合规。

### 4.5 两路获取与终止条件审查

走查 `zs_offsets.c`：
1. **获取顺序**：优先尝试 `calculate_btf_offsets()`；仅在返回 `-ENODATA`（BTF 不存在或未启用）时回退到 `calculate_function_offsets()`。有效 BTF 解析失败时保留错误，不盲目回退。
2. **终止校验**：
   - 6 项字段（`crypto_alg_flags`, `crypto_alg_name`, `crypto_alg_compress`, `crypto_alg_init`, `crypto_tfm_ctx`, `crypto_alg_driver_name`）只要有任意一项小于 0，立即返回 `-EINVAL` 终止加载。
   - 校验名字数组跨度 `name_size = driver_name - name`，必须 `>= sizeof("zstd-kpm")`（动态兼容 64 字节与 128 字节内核布局）。
   - 边界检查确保所有字段偏移加上相应结构体大小均在 `sizeof(zstd_alg)` 范围内。
3. **禁止猜偏移**：无任何按内核版本号（如 4.4/4.14）做分支硬编码偏移的行为。

### 4.6 产物自识别与命名契约

- 产物内嵌 `.kpm.info` 的 `kp_compat` 字段：
  - `base`, `baselines`, `baselines_debug`, `debug`: 均为 `kp_compat=modern`。
  - `legacy`, `legacy_debug`: 均为 `kp_compat=legacy`。
- `offset_mode` 字段：
  - `baselines`, `baselines_debug`: 均为 `offset_mode=static`。
  - 其余 4 个实例: 均为 `offset_mode=dynamic`。
- 配置表节 `.data.re_offsets` 大小在所有 6 个产物中均为 **12 字节**（对应 6 个 `int16_t` 字段）。
- 配套 JSON 文件（`baselines.kpm.json` 与 `baselines_debug.kpm.json`）包含 6 个字段的 `-1` 模板定义，格式符合 schema 3。

### 8.2 本次未验证与未覆盖清单
