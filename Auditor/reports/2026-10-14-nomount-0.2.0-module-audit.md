## 5. 4.4 目标配置推导链与 VFS 调用 ABI 审查

### 5.1 配置字段扩容与 -1 缺项处理

NoMount 0.2.0 将配置表从 38 项（76 字节）扩容至 42 项（84 字节），原 38 项字段顺序保持稳定，新增 4 项调用 ABI 字段：
- `fop_iterate_shared = -1` 与 `dop_init = -1`：
  - Linux 4.4 原生 VFS 尚未引入 `file_operations->iterate_shared`（引入于 Linux 4.7）及 `dentry_operations->d_init`；
  - Auditor 走查源码确认：代码在 `nm_operations.c` 中对值为 -1 的槽位有显式防御分支，跳过相关代理注册，回退至经典的 `iterate` 槽位，符合 4.4 实际内核架构。

### 5.2 4 项新增调用 ABI 独立审查

Auditor 对比目标内核反汇编指令流与原生头文件声明，逐项核定 4 项新增配置：

1. **`getattr_callback_args = 3`（回调原型 3 参数）**：
   - 在 Linux 4.4 中，`inode_operations->getattr` 定义为：
     ```c
     int (*getattr) (struct vfsmount *mnt, struct dentry *, struct kstat *);
     ```
     接受 3 个参数（`mnt`, `dentry`, `stat`）。而在 Linux 4.19+ 中该接口被重构为接受 4 个参数（`const struct path *`, `struct kstat *`, `u32`, `unsigned int`）；
   - 走查 `nomount/nm_inode.c:72-75`：当配置为 3 时，注册 `nm_file_getattr_mount(struct vfsmount* mount, struct dentry* dentry, struct kstat* stat)`，内部将其封装为 `struct nm_path` 后转入通用逻辑，完全匹配 4.4 原生调用栈。
2. **`getattr_function_args = 2`（系统原生函数 2 参数）**：
   - 在 Linux 4.4 内核导出的 `vfs_getattr_nosec` 符号原型为：
     ```c
     int vfs_getattr_nosec(const struct path *path, struct kstat *stat);
     ```
     仅接受 2 个参数；
   - 走查 `nomount/nm_inode.c:32, 59-60`：当 `getattr_function_args == 2` 时，正确绑定 `nm_vfs_getattr_pair` 并在底层仅传递 `(backing, stat)`，避免了 4.19 下 4 参数传递导致寄存器错位破坏栈帧的严重风险。
3. **`kstat_inode_first = 1`（kstat 结构属性起始布局）**：
   - Linux 4.4 的 `struct kstat`（`include/linux/stat.h`）以 `u64 ino`（偏移 0）和 `dev_t dev`（偏移 8）起始；而在 4.11+ 引入 `statx` 体系后，前部被 `result_mask`、`mode`、`nlink` 等字段占用；
   - 走查 `nomount/nm_structs.h:193-202` 与 `nm_offsets.c:94-104`：当配置为 1 时，采用 `struct nm_kstat_inode_first`，正确将虚拟 inode 编号与主设备号写入偏移 0 与 8，避免属性篡改错位。
4. **`name_hash_args = 2`（哈希函数 2 参数）**：
   - 在 Linux 4.4 中，`full_name_hash(const char *name, unsigned int len)` 仅接受 2 个参数；4.6+ 之后才在首位增加 `const void *salt` 参数；
   - 走查 `nomount/nm_rules.c:6-10, 21`：当配置为 2 时，使用 2 参数包装指针，正确对接目标符号。

## 6. 卸载保护与 RA-002 适用范围继承确认

Auditor 独立走查 0.2.0 的退出逻辑：
- `nomount/nomount.c:54-58`：
  ```c
  static long nomount_exit(void* reserved) {
    if (nm_initialized)
      pr_err("NoMount: do not unload; native keyring and VFS may retain callbacks\n");
    return 0;
  }
  ```
- **技术现状与定级结论**：
  1. 模块退出函数依然未执行任何注销与代理表还原；
  2. KernelPatch 上游加载器在 `module.c:540-547` 依然无条件释放模块内存；
  3. **`RA-002` 前提依然 100% 成立**：动态卸载或重载必致 Use-After-Free 整机 Panic；
  4. **约束确认**：在 4.4（Nokia 7 plus）上的测试与交付必须严格继承并维持「`post-kernel-init` 嵌入加载，常驻至重启，**严禁卸载与动态重载**」的安全红线。

## 7. CFI 条件在 4.4 内核上的适用性审计

依据已解包的内核配置（`894938f7…`）：
- 目标内核 `4.4.192-perf+` 为 GCC 4.9 构建，未启用 Clang CFI（`CONFIG_CFI_CLANG` 在该版本内核上尚未引入）；
- KernelPatch `secpass.c:96-100` 已明确声明此种情况下提示 `no symbol for pass kcfi`，但对 non-CFI 内核（<= 5.4）不构成致命错误；
- Tester 在 4.4 真机加载时，CFI 前置条件应按 DEV-034 修订后的准则核验，若无 CFI 符号应如实记为「未验证/不适用」，不阻断基础功能测试。

## 8. 变换工具负向拦截测试

Auditor 在沙箱中对 `patch_offsets.py` 实施负向拦截测试，结果如下：
1. **缺失偏移字段拦截**：删减 `name_hash_args` 字段，工具报错 `error: offset fields differ: missing=['name_hash_args']`（退出码 1，PASS）；

3. **坏 ELF 文件拦截（legacy-kp）**：输入畸形非 ELF 文件，工具报错 `error: expected ELF64 little-endian KPM`（退出码 1，PASS）；
4. **输出覆写保护**：尝试覆写已存在的归档文件，工具拦截并报错 `error: output KPM or layout already exists; choose a new path`（退出码 1，PASS）。
