## 3. 结论摘要

- **独立复现通过的检查**：
  - **独立重编译**：在无缓存独立沙箱下，4 份普通候选產物 SHA-256 及 2 份配套布局 JSON 与在册记录 **100% 逐字节吻合**；
  - **节区与重定位**：4 份候选产物必需节区 `.kpm.info`、`.kpm.init`、`.kpm.ctl0`、`.kpm.exit` 齐备，函数入口重定位（`R_AARCH64_ABS64`）合法；
  - **静态布局契约**：两份 `baselines*` 的 `.kpm.json` 为 schema 3，配置表节大小为 12 字节（6 项 `int16_t`）；偏移均为模板值 `-1`，未声称可直接加载；
  - **zstd-kpm 注册名与并存安全**：模块算法名由 `zstd` 调整为 `zstd-kpm`，规避了与内核原生 `zstd` 的注册冲突；多核编解码上下文为 per-tfm 独立动态分配，零全局可变共享状态，无数据竞争风险；
  - **生命周期机制**：`zram_zstd_exit` 不主动调用 `crypto_unregister_alg`，符合 `RA-001` 接受的常驻模块规范（不可卸载、不可重载），避免注销竞态与 UAF；
  - **双路布局推导**：
    - **BTF 路径**：在现代内核上优先读取内核原生 BTF 类型定义，具有极高的确定性；
    - **函数推导路径**：通过 `zs_structs.h` 确立 4.4～6.6 稳定公共前缀，并针对无 `lzo_init` 的 5.10 内核通过 `crypto_cts_exit_tfm` 提取上下文偏移，约束严格，推导失败即返回错误终止，符合“不猜偏移”铁律；
  - **代码规范与安全扫描**：`clang-format` 0 报错；静态扫描 0 阻塞性漏洞。
- **边界说明**：
  - 本轮候选集**不包含旧 KP（4.4）派生件**；若后续有 4.4 真机测试或交付需求，将按二进制后变换规则另行产出派生记录并由 Auditor 独立复核。

### 4.3 zstd-kpm 注册并存与生命周期安全独立评估

审计请求专项重点：*模块改为 `zstd-kpm` 注册名并要求与原生 `zstd` 并存，判断是否引入新的注销、引用或并发风险*。

Auditor 独立审查源码及 Linux Crypto API 机制：
1. **并存与注册冲突消除**：
   - 在 0.3.0 及早期实现中，算法名称注册为 `"zstd"`。当目标内核（如 Android GKI 或厂商内核）已内建或编译了原生 `zstd.ko` 时，调用 `crypto_register_alg` 将发生名称冲突（返回 `-EEXIST`）或替换原生驱动，导致不可控的交互；
   - 0.4.0 显式将 `cra_name` 与 `cra_driver_name` 改为 `"zstd-kpm"`，加载前执行 `crypto_has_alg("zstd-kpm", ...)` 校验。由于名称唯一，**完全实现了与内核原生 `zstd` 的无冲突并存**；
   - zram 设备可通过 `/sys/block/zram0/comp_algorithm` 显式写入 `zstd-kpm` 选用本模块算法，原生 `zstd` 保持原状，互不干扰；
2. **并发与多核安全性**：
   - `zstd_prepare` 为每个 `crypto_tfm` 单独通过 `vzalloc` 分配独立的 `cwksp` 与 `dwksp`，并初始化独立的 `cctx` 与 `dctx`；
   - 运行期在 `zstd_compress` 与 `zstd_decompress` 中，上下文指针从入参 `tfm` 获取（`zstd_context(tfm)`），只操作当前线程/当前流持有的上下文；
   - 模块内无任何跨 stream 或跨 CPU 的全局可变状态（`zstd_alg` 在注册后只读，`registered` 为单次布尔状态），**在多核并发压缩/解压场景下具备完全的线程安全性，零并发数据竞争**；
3. **注销与引用风险**：
   - `cra_module` 设为 `NULL`（因为 KPM 不属于内核标准 `struct module`，无法依赖标准模块引用计数 `try_module_get`）；
   - `zram_zstd_exit` 中仅打印日志，不调用 `crypto_register_alg` 的对应反向接口。如果内核正在使用 `zstd-kpm`，强制卸载 KPM 模块代码将导致后续回调触发 UAF；
   - **结论**：该行为与 `RA-001` 的书面风险接受完全一致——**模块设计为开机加载后永久常驻，禁止运行时卸载和二次加载**。此生命周期改动没有引入新的注销缺陷，而是严格维持了已知安全边界。

### 4.4 布局来源双路推导独立判断

审计请求专项重点：*布局来源分为 BTF 与函数推导两路，对两条路径分别给出独立判断*。

Auditor 对两条推导路径的独立评估如下：

#### 路径 A：BTF 动态推导（`zs_btf.c:calculate_btf_offsets`）
- **适用场景**：5.10+、5.15、6.1、6.6 等内嵌 vmlinux BTF 的现代内核；
- **推导机制**：
  1. 通过 `bpf_get_btf_vmlinux` 获取内核内嵌 BTF 符号句柄；符号不存在时返回 `-ENODATA` 优雅降级回退至函数推导；若内核 BTF 存在但解析异常（`IS_ERR`）则直接返回错误，不盲目乱退；
  2. 精确匹配 `struct crypto_alg` 与 `struct crypto_tfm` 类型；
  3. 读取 6 项关键偏移：`cra_flags`, `cra_ctxsize`, `cra_name`, `cra_driver_name`, `cra_u.compress.coa_compress`, `cra_init`, `__crt_ctx`；
  4. 实施严密的前缀与连续性断言：
     - 验证 `cra_flags`、`cra_ctxsize`、`cra_name` 必须严格等于 `struct zs_crypto_alg_prefix` 编译期偏移；
     - 验证 `coa_decompress` 必须紧邻 `coa_compress`；
     - 验证 `cra_exit` 与 `cra_module` 必须紧邻 `cra_init`；
     - 验证 `name.size >= sizeof("zstd-kpm")` 且 `driver_name` 紧随 `name`；
- **独立判断**：
  **高度确定且安全**。BTF 是内核官方类型元数据，直接反映内核真实的编译布局，杜绝了指令反汇编的歧义。校验断言全面覆盖了结构体重排或扩容风险，一旦内核结构布局不符合假设立即报错拒绝，可靠性极高。

#### 路径 B：函数反汇编推导（`zs_offsets.c:calculate_function_offsets`）
- **适用场景**：4.4、4.9、4.14、4.19 及部分 5.10 等无 BTF 内核；
- **推导机制**：
  1. **共同稳定前缀**：利用 `zs_structs.h` 中经 4.4～6.6 内核头文件与多机型二进制实证的共同前缀，`flags`（`0x20`）与 `name`（`0x38`）直接由结构体常量确立；
  2. **`driver_name`**：反汇编 `crypto_check_alg` 首个参数字节读取（或 `crypto_register_alg` 的入口参数检查），确定名称跨度；
  3. **`compress`**：反汇编 `crypto_compress` / `crypto_comp_compress`，在 16 条指令窗口内识别从 `tfm->__crt_alg` 读取回调函数指针的 `LDR` 指令，并容忍至多 3 条 CFI 准备指令；
  4. **`init`**：反汇编 `crypto_mod_get`，在入口前 8 条指令识别读取 `cra_module` 的偏移，利用四指针连续性（`init, exit, destroy, module`）回减 `distance` 获得 `init` 偏移；
  5. **`ctx`（关键演进）**：
     - 优先反汇编 `lzo_init` 前 16 条指令的首个 64 位写入；
     - 若内核缺少 `lzo_init`（如 Android 12 / 5.10 GKI），自适应切换为反汇编 `crypto_cts_exit_tfm`：在前 8 条指令内定位读取 child 后的 base 指针计算与 `crypto_destroy_tfm` 调用，由 `load_offset - add_offset` 获得 `__crt_ctx`；
  6. **防御与终止**：
     - 指令跟踪严格执行寄存器保守失效（`parameter_regs_after`），防止指令别名覆盖缺陷（DEV-030 修复保持有效）；
     - 边界检查确保各字段偏移位于 `sizeof(zstd_alg)`（1024 字节）合法范围且相互不重叠；任何一项为负或校验失败立即返回 `-EINVAL`。
- **独立判断**：
  **设计严谨，解决了 5.10 缺少 `lzo_init` 的兼容断层**。函数推导路径引入了基于 CTS 的新推导点，闭环了 Android 12 / 5.10 场景；同时保留了极高标准的终止条件，完全避免硬编码或按版本号瞎猜偏移，符合项目铁律。
