## 5. 挂载上下文与原生权限分派回调 ABI 及语义审查

### 5.1 45 字段配置表扩容与默认值验证

配置结构体 `struct struct_offset` 由 42 项扩充至 45 项（90 字节）：
```c
struct struct_offset {
  // ... 42 项既有字段保持原有顺序与偏移 ...
  int16_t permission_abi;
  int16_t fillattr_abi;
  int16_t getattr_context_kind;
};
```
在模板中，三个新字段默认值均为 `-1`。在 `nm_validate_inode_offsets` 中：
- `permission_abi`、`fillattr_abi`、`getattr_context_kind` 任何一项为负数（未配置）时，均返回 `-ENOENT` 拒绝加载；
- 检查约束 `(offsets->getattr_callback_args == 5) != (offsets->getattr_context_kind != 0)`，即 5 参数回调必须且仅在有上下文时允许。

### 5.2 挂载上下文结构体与 `mnt_userns` 偏移核验

在 5.15 等带用户命名空间的内核中，原生 VFS 权限与属性回调需要传递 `struct user_namespace *`。
KPM 中声明：
```c
struct nm_mount_context_head {
  struct dentry* root;         // offset 0 (8B)
  struct super_block* super;   // offset 8 (8B)
  int flags;                   // offset 16 (4B + 4B padding)
  union {
    struct user_namespace* userns;
    struct mnt_idmap* idmap;
  } context;                   // offset 24 (8B)
};
```
**Auditor 独立 BTF 核验**：
在 Sony 5.15 内核 BTF 中解析 `struct vfsmount`：
- `mnt_root`: offset 0, ptr to `dentry`
- `mnt_sb`: offset 8, ptr to `super_block`
- `mnt_flags`: offset 16, `int`
- `mnt_userns`: offset 24, ptr to `user_namespace`
`context` 偏移量 24 字节与目标内核 `vfsmount` 布局完全吻合。

### 5.3 原生权限分派 `permission_abi` 审查

`nm_backing_permission` 实现了对目标原生权限检查函数的分派：
- `permission_abi == 0`（Android 4.4/4.19）：调用 `inode_permission2(mount, inode, mask)`。
- `permission_abi == 1`（Plain Linux 5.10）：调用 `inode_permission(inode, mask)`。
- `permission_abi == 2`（Linux 5.15）：从 `path->mnt` 的偏移 24 读取 `userns`，调用 `inode_permission(userns, inode, mask)`。
- `permission_abi == 3`（未来 idmap）：调用 `inode_permission(idmap, inode, mask)`。

**安全防御性审查**：
- 若 `path` 为空、`path->dentry` 为空或 `path->mnt` 为空，返回 `-ENOENT`；
- 在 `abi == 2` 或 `abi == 3` 时，若 `mount->context.userns` 为 NULL，返回 `-EINVAL`，绝不解引用空指针；
- 在准备阶段，若 `abi >= 2`，严格强制 `getattr_context_kind == abi - 1`，防止权限 ABI 与属性 ABI 错配。

### 5.4 属性回调 `fillattr_abi` 与 `getattr_context_kind` 审查

- `getattr_context_kind == 1` 时，虚拟目录注册 5 参数回调 `nm_virtual_directory_getattr_userns`，原型接收 `(struct user_namespace *userns, const struct nm_path *path, struct kstat *stat, u32 mask, unsigned int flags)`；
- 内部调用 `generic_fillattr` 时，若 `fillattr_abi == 3`，以 `(userns, inode, stat)` 3 参数调用原生 `generic_fillattr`；
- **上游一致性**：对照 upstream nomount 源码（`nomount.h` 第 310-312 行与 `nomount.c` 第 554 行），上游在 5.15 内核中通过宏定义 `IDMAP_ARG` 展开为 `struct user_namespace *mnt_userns,`，并在属性填充时传递 `mnt_userns`。KPM 的设计严格保持了与上游固定 LKM 的一致性。

### 5.5 5.15 / 5.10 / 4.19 / 4.4 配置推导链核验

| 目标 | `permission_abi` | `fillattr_abi` | `getattr_callback_args` | `getattr_context_kind` | 对应原生 API 原型 |
| --- | --- | --- | --- | --- | --- |
| Sony / GKI 5.15 | 2 (`user_namespace`) | 3 (`userns`, `inode`, `stat`) | 5 | 1 (`mnt_userns` @ 24) | `inode_permission(userns, ...)` |
| Android13 5.10 | 1 (`inode`, `mask`) | 2 (`inode`, `stat`) | 4 | 0 (无) | `inode_permission(inode, mask)` |
| Sony 4.19 | 0 (`inode_permission2`) | 2 (`inode`, `stat`) | 4 | 0 (无) | `inode_permission2(mnt, inode, mask)` |
| Nokia 4.4 | 0 (`inode_permission2`) | 2 (`inode`, `stat`) | 3 | 0 (无) | 3 参数 getattr 回调 |

全部目标推导链均与目标内核二进制 / BTF 中的符号和类型签名一一对应。

## 6. 卸载保护与 RA-002 适用范围确认

- **审查事实**：
  NoMount 0.3.0 仍采用挂钩文件系统操作表（`f_op`、`i_op`、`d_op`）并劫持活动超级块的架构；
  代码中未实现动态清理与解挂钩的 `kpm_exit`，且活动文件系统中存在对模块内存中操作表函数的持久指针引用。
- **结论**：
  **RA-002（卸载导致内核崩溃危害）在 NoMount 0.3.0 上 100% 成立**。
  维护者已登记该缺陷并将其范围正式扩展至 0.3.0，用户已批准常驻约束。模块必须**常驻运行至设备重启**，严禁在运行时进行动态卸载或重载。
