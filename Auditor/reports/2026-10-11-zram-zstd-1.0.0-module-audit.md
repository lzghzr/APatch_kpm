## 3. 结论摘要

- **独立复现通过的检查**：
  - **独立重编译**：在隔离沙箱无缓存环境下，4 份普通候选产物 SHA-256 及 2 份配套布局 JSON 与在册记录 **100% 逐字节吻合**；
  - **ELF 节区与自解析**：必需入口节区 `.kpm.init`、`.kpm.ctl0`、`.kpm.exit` 齐备（8 字节入口），重定位（`R_AARCH64_ABS64`）合法；`.kpm.info` 内嵌版本标识为 `1.0.0`（非 debug）/ `1.0.0_d`（debug）；
  - **静态布局契约**：两份 `baselines*` 的 `.kpm.json` 为 schema 3，对应配置表节大小为 12 字节（6 项 `int16_t`）；偏移均为模板值 `-1`，未声称可直接加载；
  - **新增算法列表显示机制（`zs_display.c`）**：
    - **缓冲区容量防护**：通过 `4096 - ((uintptr_t)buf & 4095)` 约束剩余写入长度，严密防范跨 4 KiB 子页溢出；
    - **重复项与格式检查**：完整匹配空格/制表符/换行分隔的独立 token（`zstd-kpm` / `[zstd-kpm]`），防止重复追加；严格校验结尾换行与返回长度；
    - **加载状态守卫**：安装 hook 受到内核原生 `module_mutex` 互斥保护，并明确检查模块状态必须为 `ZS_MODULE_LIVE`，严禁对正在初始化的 `COMING` 模块安装 hook；
    - **故障隔离与降级**：显示 hook 失败仅输出日志降级，不影响已成功注册的 `crypto_register_alg`，用户仍可直接指定选用 `zstd-kpm`；
  - **版本跃迁（0.4.0 → 1.0.0）评估**：
    - 算法注册名称（`zstd-kpm`）、驱动名、Crypto API 回调、内存分配模型与双路（BTF / 函数反汇编）推导机制与 0.4.0 保持一致；
    - 版本提升反映了引入 zram `comp_algorithm` 可见性后的功能闭环，未引入未披露的接口或破坏性行为变化。
- **边界说明**：
  - 本轮候选集**不包含旧 KP（4.4）派生件**；若后续有 4.4 真机测试需求，另行按构建后字节变换规则生成派生件并独立审计。

### 4.3 新增算法列表显示机制（`zs_display.c`）独立边界与安全审计

审计请求专项重点：*审查新显示路径的边界（列表长度、缓冲区、并发只读语义）与是否影响既有注册/生命周期*。

Auditor 独立深入审查源码：
1. **缓冲区容量防护（越界写防御）**：
   ```c
   size_t capacity = 4096 - ((uintptr_t)buf & 4095);
   ```
   - 在 Linux 内核中，sysfs 文件读取分配一页缓冲区（PAGE_SIZE，ARM64 上通常为 4 KiB、16 KiB 或 64 KiB）；
   - 代码使用 `4096 - ((uintptr_t)buf & 4095)` 精确计算出当前 4 KiB 子页内剩余可用字节数，不论内核页大小是 4 KiB 还是更大，均能严格防御跨页越界写；
   - 写入前检查 `prefix + space + sizeof(suffix) > capacity`（包含结尾 NUL），保证任何情况下均不会超出缓冲区边界；
2. **列表解析与重复项防御**：
   - `display_has_algorithm` 逐 token 扫描缓冲区，仅当匹配独立分隔的 `"zstd-kpm"` 或选中项 `"[zstd-kpm]"` 时判定存在；
   - 如果列表中已存在 `zstd-kpm`，直接返回退出，防止多次调用追加重复算法名；
3. **并发调用与只读语义**：
   - sysfs 读取操作（用户态读取 `/sys/block/zram0/comp_algorithm`）发生在各自独立分配的每请求内核页缓冲区中；
   - `zstd_list_after` 仅在自己的缓冲区内操作，不修改任何全局共享变量；
   - 因此在多线程并发读取 `comp_algorithm` 时，**具备完全的重入性与线程安全性，无并发数据竞争**；
4. **Hook 安装安全性与生命周期互斥**：
   - 安装过程 `install_zram_display` 显式持有内核原生全局锁 `display_mutex_lock(display_module_mutex)`（即 `module_mutex`），序列化安装；
   - 使用原子操作 `__atomic_load_n(&display_installed, __ATOMIC_ACQUIRE)` 实现单次安装幂等性；
   - **`COMING` 状态守卫**：检查所有者模块状态必须为 `ZS_MODULE_LIVE`。如果模块尚处于 `MODULE_STATE_COMING`（正在加载初始化），则跳过安装，防止对未完全初始化的模块注入 hook 导致竞争；
   - 对未加载 zram 的系统，hook 拦截 `do_init_module` 的返回，在模块成功加载完成（`args->ret == 0`）后被动触发安装，机制闭环；
5. **故障隔离与降级机制**：
   - 若 `module_mutex`、`zcomp_available_show` 等符号不可用，或 `hook_wrap` 失败，模块仅打印日志告警；
   - 算法向内核 Crypto API 的注册（`crypto_register_alg`）早已在 `start_zram_display` 调用前成功完成；
   - 显示 hook 的任何失败均不阻断算法使用，用户依然可以直接向 `/sys/block/zram0/comp_algorithm` 写入 `zstd-kpm` 选择算法，功能具备高度容错弹性。

### 4.4 版本跃迁（0.4.0 → 1.0.0）接口与行为变化评估

审计请求专项重点：*判断版本号自 0.4.0 提升至 1.0.0 是否有未披露的接口或行为变化*。

Auditor 执行跨版本源码全面对比（`diff 0.4.0..1.0.0`）：
1. **核心算法接口无变化**：
   - Crypto API 算法名称（`"zstd-kpm"`）、驱动名称（`"zstd-kpm"`）、标志位、优先级及压缩级别（Level 3）保持原样；
   - 编解码回调实现、动态工作区分配（`vzalloc` / `vfree`）及初始化自检（`codec_check`）逻辑未发生任何改动；
2. **偏移推导机制无变化**：
   - BTF 路径（`zs_btf.c`）与函数推导路径（`zs_offsets.c`，含 CTS 降级路径与指令别名失效机制）完全保持原样；
   - 配置表节 `.data.re_offsets` 结构体字段与 12 字节长度完全未变；
3. **控制接口（ctl0）保持稳定**：
   - `zram_zstd_ctl0` 彩蛋响应字符串 `_(._.)_` 及交互协议无任何变更；
4. **唯一增量变更**：
   - 本次跃迁的全部新增代码集中于 `zs_display.c`，目的是增强与系统开机脚本/用户态工具的友好度（使 `cat /sys/block/zram0/comp_algorithm` 能直观看到可用的 `zstd-kpm`）；
   - **结论**：版本号自 0.4.0 提升至 1.0.0 属于功能完备后的里程碑版本升级，**不存在任何未披露的隐性行为改动或破坏性兼容风险**。

### 4.5 静态基线布局契约
